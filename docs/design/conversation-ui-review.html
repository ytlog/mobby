1. 建议结论

采用「对话列表首页 → 全屏对话 → 全屏详情」的 Android 页面导航。首版围绕 360–430dp 手机竖屏设计，兼顾 320dp 小屏、横屏、分屏和大字体。对话列表不再以桌面常驻侧栏或侧滑抽屉作为主入口，详情不再挤在右侧。

保留 Codex 的内容组织方式：用户消息、执行过程、最终答复分层；视觉使用中性色与轻量分隔。控件、返回、输入法、权限和后台生命周期按 Android 习惯实现。首版只有“对话”一个主要目的地，不为了模仿客户端增加底部多 Tab；设置从列表工具栏进入。

核心体验：当前轮次的执行过程最初展开；正常完成后自动收起未被用户手动操作的过程；最终答复、错误、待确认事项始终留在主时间线。 折叠只改变展示，不删除历史。

本次交付为可离线打开的完整 HTML 设计文档，包含可点击的手机交互草图，供确认方向。文中数据、文件改动和运行结果均为示例，不代表实际执行。用户所说的“Cloud 客户端”暂按 Claude 客户端理解。

Android 交互依据

  • Android 布局和导航：选择用户熟悉的页面导航与主操作；本文采用列表—详情路径，新建用 FAB。
  • Compose Predictive Back：系统返回预览实际目的地，取消手势不能提前更改页面或草稿。
  • Compose Window Insets：按状态栏、导航栏、显示切口和 IME 的实际 inset 布局。
  • Compose 无障碍默认行为：保证交互目标至少 48 × 48dp，并提供清楚的语义描述。

Android 规范支持的是平台行为；列表首页、首版不使用底部导航等仍是本项目的产品设计决策。本文不承诺当前依赖版本已覆盖全部预测返回动画，实施时需检查并做设备验证。

3. 代码现状与设计前提

以下是静态代码检查事实，未据此声称手机运行验收通过：

  • MainActivity.kt 的 TestConsoleScreen 当前展示运行状态、Agent 切换、文本输出列表和输入框。
  • TestConsoleViewModel.kt 绑定 RuntimeService，只有一个输入草稿和一个运行状态。
  • RuntimeService.kt 只允许一个忙碌任务，输出存于内存；最多保留 2,000 行、约 1,000,000 字符，单项会截断。不能直接用它作完整会话数据库。
  • AgentAdapter.kt 将 Claude stream-json / Codex exec --json 事件转为 AgentOutput(text, error)，UI 已失去工具调用 ID、轮次和事件阶段。
  • 当前命令参数没有恢复既有 CLI 会话的路径。增加历史列表并不自动获得多轮上下文连续性。
  • 已有 Compose、协程、libtermux、前台服务和加密网关存储应继续使用。

因此需先改事件模型、会话持久化与 CLI 会话绑定，再构建交互。不能从日志里匹配“完成”几个字来折叠，不能把 stdout 每一行当作一条完整回复。

4. Android 页面与组件

4.1 页面层级

列表首页 → 对话页 → 执行详情页。设置页由列表首页进入；通知直接打开对应运行对话，并建立可返回列表的页面栈。恢复启动时可回到最近对话，但应用根目的地仍是列表。HTML 顶部草图从执行中的对话开始，便于观察折叠；“返回”可体验列表。

页面内容与主要动作Android 组件建议
对话列表标题搜索、置顶/最近、会话状态；右下新对话；工具栏设置Scaffold、TopAppBar、LazyColumn、ExtendedFloatingActionButton
对话页顶部返回、标题、更多；时间线；底部输入区Scaffold、TopAppBar、LazyColumn、TextField
执行详情返回、工具名称、状态；完整可用日志；显式复制入口独立 navigation destination；SelectionContainer

网关设置两种 Agent 的真实配置表单；保存错误就地提示独立全屏表单；密钥默认隐藏

对话列表每行建议至少 72dp，标题最多两行，副行显示 Agent、时间和文字状态。整个会话行可点击；更多按钮有独立 48dp 目标且不与行点击重叠。可长按打开操作面板，但所有动作也能通过显式“更多”完成。首版不使用滑动删除或自定义屏幕边缘手势。

4.2 手机布局尺寸与视觉

  • 主页面水平边距 16dp，段落间距 12–16dp，工具步骤行至少 48dp；这些是设计初值。
  • 顶部栏内容高约 64dp，另计系统状态栏 inset；返回与更多按钮位于两端，中间标题省略。点击标题可在会话信息中查看完整 Agent / 工作区。
  • 正文 16sp，次要信息 12–14sp，标题 20–22sp；使用系统字体与动态字号，不把文字大小固定成 px。深浅色都要保证对比度。
  • 输入区固定在键盘或系统底栏上方，不随消息滚走；多行输入建议 1–5 行，超过后输入框内部滚动。发送/停止始终有至少 48dp 点击目标。
  • Agent 消息无大气泡；用户消息浅色气泡靠右。过程外层仅轻分隔；错误使用图标和文字，不只变红。
  • 全屏日志可纵向滚动，代码行可单独横向滚动。普通正文和主页面不可横向溢出。

4.3 横屏、分屏和大字体

首版所有手机窗口保持单栏，按可用宽度重排；不依据横屏自动切为三栏。宽度大于 600dp 时正文居中并限制阅读宽度，列表仍独立一页。平板双栏留到后续范围。原 v1 的 1200dp 三栏方案退出本次设计。

320dp 下标题可省略、次要信息换行，不能缩小触区。200% 字号时按钮与摘要行允许增高，底部面板可全展开并滚动；短横屏优先保住输入和返回，减小非必要留白。HTML 草图的 CSS px 只是近似尺寸，不能替代真机 dp/sp 验收。

4.4 返回与页面状态

当前状态系统返回结果不应发生的副作用
输入法正在显示先交给系统收起输入法不发送、不清空草稿、不退出对话
有底部面板/对话框关闭最上层；若面板中 IME 可见，先处理 IME不把关闭视作同意或拒绝权限
执行详情页返回原对话原位置不结束命令、不重新请求输出
对话页返回列表；保留草稿与折叠状态不停止运行任务
列表根页按系统行为回到启动来源/桌面不拦截为“双击退出”，不强杀服务

工具栏返回表示页面向上导航：直接回父页并随离开清除焦点；与系统返回先收 IME 的行为区分。导航栈使用 Navigation Compose 单一来源，避免反复切换会话堆积同一页。Predictive Back 遵循系统与组件能力，仅在手势提交后弹栈；取消手势保持原状态。不占用左右边缘与系统返回争抢手势。

4.5 键盘与触摸

点击输入框才唤起 IME，进入历史对话或从详情返回不自动弹键盘。软键盘回车默认换行，发送由独立按钮触发，避免中文输入候选确认时误发送。发送成功不强制收键盘，便于继续写草稿；点击停止不清空输入。

使用 edge-to-edge 与实际 WindowInsets：顶部内容避开状态栏/切口，底部输入区同时处理 navigationBars 与 IME 的消费关系，不能把两种高度重复叠加。消息区域随键盘可用空间缩小；在底部阅读时保持末项可见，阅读历史时保留锚点。设备三键导航与手势导航分别验收。

长按文字使用 Android 文本选择/复制菜单；关键动作不依赖 hover、右键或双击。折叠标题整行可点，TalkBack 宣读状态、步骤数与展开状态。新增 token 不逐条播报；完成、失败、待处理变化以低干扰方式播报。

5. 时间线结构

一段对话包含多个轮次，每轮按以下顺序组织：用户消息 → Agent 的公开进度说明与工具事件 → 最终答复 → 产物入口。过程按真实时间顺序显示，不将晚到日志插入其他轮次。

内容默认呈现允许折叠
用户消息浅色气泡、保留原文长文本可“展开全文”，不随运行结束折叠
公开进度说明普通段落；过程中按事件顺序显示完成后随过程组收起
计划CLI 确有计划事件才显示步骤与状态可折叠，不能伪造完成百分比
工具调用名称、简述、状态、耗时外层过程初始展开，内部长输出默认只露摘要
最终回复Markdown 正文不自动收起
文件 / 产物紧凑入口，显示真实可用项目数详情单独打开
权限请求待处理卡片 + 操作范围未处理时不可被父级折叠遮住
失败 / 超时 / 停止明确结果与后续动作状态摘要始终可见，日志可折叠
未识别事件“暂不支持展示的事件” + 脱敏详情不丢弃、不算成功步骤

“过程”仅指 CLI 提供的公开说明、工具活动与输出，不展示或推测模型隐藏思维链。非流式网关等待期间显示“等待响应”，收到真实事件后再更新；不伪造逐字输出、步骤或进度。

6. 展开与折叠：明确规则

每轮设 expansionOverride = AUTO | OPEN | CLOSED，每个工具详情另有独立开关。业务状态与展开状态分开保存。

触发AUTO 默认行为已有用户选择时
新轮次开始过程组展开；当前步骤显示摘要新轮次有独立状态
步骤正常完成、整轮仍在运行保留步骤行；长输出收为摘要手动打开的步骤详情保留
整轮确认成功最终回复已写入后，过程组收为一行OPEN 保持展开；CLOSED 保持收起
失败、超时、取消、异常中断过程保留展开；显示常驻结果条可保持过程收起，但异常摘要必须在组外
权限请求或需要回答待处理卡片放组外；列表标“待处理”折叠选择不影响卡片
切换对话 / 屏幕旋转恢复该轮选择与阅读位置不重置
打开历史成功轮次默认折叠持久化 OPEN / CLOSED 优先

完成时的自动折叠须同时满足：没有未完成步骤或待处理请求、结果事件及退出状态一致、用户未手动选择、用户没有在过程内选中文本或停留阅读。用户上滑阅读时推迟本次自动折叠，提供“收起过程”入口；不要一空闲就突然收起。回到底部或重新进入对话后才重新应用 AUTO 默认值。

展开动画建议 160–220ms，遵守减少动画设置。折叠前记住首个可见项 ID 与偏移并恢复，保持视口锚点。焦点位于即将隐藏区域时延迟折叠。展开按钮语义包含“已展开/已折叠、步骤数、状态”。

摘要示例：已完成 · 5 个步骤 · 32 秒、已结束 · 1 个步骤失败、已停止 · 部分操作可能已执行。工具失败后恢复成功时仍保留“含 1 次失败，后续已恢复”标记与入口；不得把错误历史改写为全部成功。

7. 具体交互流程

新建与继续

列表为空时显示“在本机开始一个任务”和“新对话”。点击新对话打开底部配置面板，选择 Shell / Claude Code / Codex 与已授权工作区后进入空对话页。首条发送后固定 Agent 和工作区，切换 Agent 新建对话。模型改动仅影响后续轮次，历史只存配置引用。缺少依赖或网关时显示配置入口并保留草稿。只有服务确认接收并持久化轮次后才清空输入；提交失败保留原文并提示原因。首条消息生成可编辑标题；首版可用本地截取，不额外调用模型。

继续对话使用绑定的 CLI session ID，恢复能力需对内置 CLI 的实际版本验证。恢复失败必须说明“无法恢复会话”，提供重试恢复或新对话，不得悄悄启动无上下文的新任务。Shell 每次启动独立命令，标题旁注明“工作目录保留，进程内变量不跨轮次保留”。

执行、停止与重试

首版全局单任务运行。用户可切换并阅读其他对话、编辑各自草稿；其他对话发送区显示“另一个对话正在执行”及跳转入口，不自动排队，也不通过 UI 暗示已接受任务。运行中继续输入仅保存草稿，首版不做中途消息注入。

停止按钮立即转为“停止中”，重复点击禁用。确认进程组终止后才标“已停止”；终止确认失败显示“停止状态待核实”，不释放运行锁或伪装成功。停止与完成竞态由已记录终态和执行证据判定，不由最后一条 UI 文案决定。

失败提供“编辑后重试”；重试创建新轮次，旧轮次保留。不得自动重发已可能产生副作用的命令。后台通知点按回到实际运行对话；后台期间折叠规则与前台一致。系统通知权限被拒绝时仍在应用列表和对话页显示真实运行状态；不得声称通知已送达。前台服务遵守系统启动与时限约束，切到后台不承诺永不终止。通知锁屏内容默认只显示任务状态，不包含命令、密钥或正文。

权限与中断

仅在适配器能接收真实请求并可靠回传决定时启用“允许本次 / 拒绝”。显示命令、目录、影响范围；默认不提供绕过沙箱或永远允许。当前非交互执行路径能否支持此交互尚未验证：未接通时显示能力限制与错误，不展示无效批准按钮。

进程重建先检查运行服务是否仍持有执行实例；若无法关联活跃实例，则记录“上次执行中断，结果未确认”，保留输出与草稿，不自动重发。切换对话不会停止任务；归档不等于停止。首版禁止归档运行中的对话，并明确说明原因。

滚动和详情

处于底部时跟随新输出；用户上滑、选中文本时暂停跟随，底部显示“有新内容 ↓”。详情返回保持原轮次、草稿和滚动锚点。正文代码块允许独立横向滚动，页面本身不横向溢出。系统返回与工具栏返回按第 4.4 节区分处理，不附带停止副作用。

对话管理

列表标题最多两行，工具栏标题单行省略；长按/更多菜单支持重命名、置顶和归档。归档支持撤销，不删除 HOME 或工作区。搜索首版仅标题；列表按最近用户提交或轮次结束更新排序，流式 token 不触发重排。选中的对话不因排序跳走；未读完成标记在用户打开后清除。永久删除和全文搜索后置。

GatewayStore：继续负责加密配置，UI/Repository 仅持有非敏感引用

导航图建议为 Conversations → Conversation(id) → RunDetail(runId, stepId)，Settings 为根页的兄弟目的地；配置与更多操作作为临时 sheet 状态。SavedStateHandle 只放目的地 ID 与轻量状态；长消息与日志放数据库/文件，避免 Bundle 过大。输入草稿持续持久化，不能只依赖 remember；Lifecycle 恢复后按 runId 重新订阅既有执行，不重发命令。

在现有 app module 中按 conversation/ui、conversation/domain、conversation/data、runtime/adapter 分包即可；首版不急于拆成多个 Gradle module。保留 RuntimeService 执行归属，Compose 和 ViewModel 不直接持有子进程。

事件包括 RunStarted、Progress、TextDelta、ToolStarted、ToolOutput、ToolFinished、ApprovalRequested、ArtifactProduced、FinalMessage、RunFinished、UnknownEvent。这是内部模型草案，不声称是两套 CLI 的原生字段名。

同一 run 内串行接收并分配单调序号；以真实 event ID 去重，缺少 ID 时通过适配器区分快照与增量，不能仅凭相同文本去重。以 providerCallId 配对工具事件；终态不被迟到进度覆盖。结果文本去重依赖消息 ID 与协议角色，不使用全文相同判断，避免丢掉合法重复内容。

状态与成功判定

CREATED → STARTING → RUNNING ↔ WAITING_FOR_USER → SUCCEEDED / FAILED / TIMED_OUT / CANCELLED / INTERRUPTED；停止请求进入 CANCELLING。状态由 reducer 处理，不在 Composable 内凭字符串决定。

Agent 成功需要实际版本对应的完成事件、正常退出和无未决致命错误；退出码 0 但缺少协议结束事件显示“结果未确认”。Shell 使用进程退出码，不要求 Agent 结束事件。stderr 作为诊断通道，不能一概视作任务失败；工具非零退出要记录失败，但与整轮最终状态区分。未知事件保留，协议解析失败不可被当作普通成功回复。

存储与性能

引入 Room 保存会话索引、轮次及事件投影，事务写入最终回复与终态。重要生命周期事件立即落盘；文本增量可 50–100ms 合并刷新 UI，最终 flush 后才结束。采用带背压的单写入队列，不让数据库或界面卡顿导致丢终态事件。

长输出以分块文件存于 app 私有目录，数据库保存索引；UI 首屏仅加载最近轮次，历史按需分页，LazyColumn 使用稳定 key。建议首版每 run 输出预算 10 MiB，达到预算显示“日志已截断”并保存状态事件、失败摘要及结尾窗口；阈值须设备测试再定，不能默默删旧输出。

网关密钥和真实配置继续只进现有加密存储。CLI 输出在持久化、显示和导出前经过脱敏；不保存包含凭证的启动命令、环境变量或完整请求头。运行参数记录只含配置引用；未知协议事件也必须脱敏。会话数据库退出系统自动备份；对话内容本身仍可能敏感，后续若加导出必须让用户选择范围。

9. 分阶段实施与验收门槛

阶段实施内容完成证据
A：结构基础用结构化事件替换文本压平；分离诊断日志；不改变网关主路径固定 CLI 版本的脱敏真实事件夹具覆盖工具、失败、完成、未知事件
B：可继续的历史Room、CLI session 绑定、草稿、单运行实例路由切换/旋转/重建后不串会话；两种 CLI 实测恢复上下文；异常如实呈现
C：对话界面列表首页、Navigation Compose、时间线、折叠、全屏详情、IME 与停止Compose 交互测试 + 320/360/412dp、横屏、IME、200% 字号验收
D：强化交互真实审批回传、文件差异、细节优化真 CLI + 模拟网关，再以手机真实网关验收

阶段 C 可先用明确标注的演示事件验证交互；产品入口不能在 B 未完成时声称支持连续对话。阶段 D 的审批未验证前不开放对应按钮。只在实际获取到文件改动信息时显示“查看改动”，不从回复文字推断。

关键验收用例：

  1. 新运行默认展开；正常结束时最终答复可见、过程变摘要；点摘要恢复步骤。
  2. 用户手动打开详情，完成事件不能关闭它；用户手动收起后新 token 不能再打开。
  3. 上滑查看历史时新输出不抢滚动，完成折叠不造成视口跳跃。
  4. 失败、超时、取消、权限请求不被父组折叠遮住；重试保留旧轮次。
  5. 切换到 B 后，A 的日志仍写 A；B 的草稿保持；全局执行锁不失效。
  6. 旋转与进程重建后历史、手动折叠、草稿恢复；无运行证据时不显示完成或自动重发。
  7. 未知事件、重复快照、迟到输出、缺少结束事件均不造成重复回复或假成功。
  8. 10,000 个输出事件下可滚动、停止可响应、内存有界；截断显式可见。
  9. TalkBack 可读出状态和展开语义；目标触区 ≥48dp；200% 大字体与键盘不遮住发送/停止；深浅色可读。
  10. 系统返回先收 IME，详情返回恢复位置；预测返回取消不改变导航；归档撤销有效；通知冷启动构建正确返回栈。
  11. 覆盖升级保留 applicationId、Keystore 别名、SharedPreferences、HOME、工作区；既有日志无法可靠迁移为对话时不伪造历史。

实施时对可复现问题先补失败回归测试，再改代码。执行项目约定的 Node/Python 测试和 JDK 17 下的 assembleDebug、单元测试、lint；变更涉及网关或 CLI 时跑对应 cli-smoke。模拟成功不等于手机或真实网关通过。本次仅设计文档，不执行完整 Android 构建。

10. Review 清单与边界

  • 手机主路径确定为列表首页 → 对话 → 全屏详情，首版不做桌面三栏或常驻侧栏。
  • 执行时默认展开，正常完成自动收起；手动操作、错误、待处理事项优先。
  • 首版多对话、单运行任务，执行中输入保存草稿；连续对话依赖真实 CLI session 恢复。
  • 会话固定 Agent 与工作区；权限按钮只在真实请求/回传链路接通后启用。
  • 首版优先命令输出详情；文件差异、并行执行、平板双栏后置。

文档内草图只演示列表切换、底部配置面板、执行状态、折叠、详情返回和键盘占位。键盘占位与“模拟系统返回”是评审控件，不是最终 App 控件。HTML 不能验证 Android 真实输入法、预测返回、前台服务、TalkBack 或 CLI；这些必须在后续 Compose 实现与设备上验收。
