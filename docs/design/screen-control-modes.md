# 屏幕操作模式

## 用户行为

Agent 根据会话选择设备动作。动作需要当前会话尚未选择的能力时，mobby 暂停该动作，并在会话中显示能力和操作的授权弹窗及记录卡。确认后补齐 Android 系统权限并添加对应标签，原动作继续执行。拒绝或超时会结束该动作。设备动作在执行前读取会话当前的权限标签，移除标签后下一次请求须重新授权。读写权限分别判断。

在「设置 → 运行环境 → 屏幕操作模式」选择：

- **当前屏幕（无障碍）**：保留原有模式，操作手机当前窗口，执行期间隐藏应用悬浮层、保持亮屏；需启用无障碍与任务通知。
- **虚拟屏幕（内置 ADB）**：无需安装其他 App；用户开启系统无线调试并在 mobby 内配对，由本机 ADB 启动同一屏幕工作进程。详情见 [内置 ADB 屏幕服务](builtin-adb-screen.md)。
- **虚拟屏幕（root）**：用户选择并连接后，通过设备现有 `su` 请求授权，启动专用于屏幕功能的工作进程；不安装 root、不改系统权限。

虚拟屏首版要求 Android 13 以上、手机亮屏且解锁；屏幕操作前检查锁屏状态。可见的副屏预览通过 View.keepScreenOn 保持亮屏，预览退出或任务结束后恢复。任务开始时创建一个 720×1280、240 dpi 的独立显示，Agent 使用 `apps` 查找应用包名，再用 `launch` 在副屏启动。任务运行时，首页、会话和其他 mobby 页面右上方显示可收起的副屏预览。已授予系统悬浮窗权限时，离开 mobby 后预览继续以系统小窗显示。预览只读；点击、滑动和输入由当前 Agent 的屏幕工具执行。

副屏登录时，Agent 可用 `request_input` 为当前可见且可编辑的输入框生成表单，也可指定当前聚焦的单个字段。留空的字段保持原值。表单只在 mobby 内显示，值通过内存交给当前副屏。提交前重新检查字段。Agent 收到填写结果，副屏在本次会话内遮蔽节点中的已填原值，并暂停向 Agent 提供截图。

任务结束、停止或宿主连接断开后释放虚拟屏及其任务内容。应用数据仍属于原应用，虚拟屏不提供分身、独立登录或独立数据。一次仅允许一个虚拟屏任务。模式切换须等待任务结束。内置 ADB 副屏断线后，屏幕操作最多等待 60 秒，用户可在屏幕操作模式中重新连接。恢复时会创建新副屏，任务需先读取副屏或打开目标应用。已发出的输入不会重放。模式保存到宿主 SharedPreferences，权限连接不跨进程重启恢复，需要重新连接。

屏幕配置页与 App 设置使用同一套圆角卡片、整行选择、分隔线、输入框、按钮和说明文字。三种模式各有一个可点击的选择行，选中标记和禁用状态与标题位于同一个操作区域。内置 ADB 的通知配对、开发者选项、数字端口输入、连接/断开，以及无障碍和通知设置入口使用相同样式。页面读取 App 的外观设置，并同步状态栏与导航栏颜色；手动选择浅色或深色后不会单独跟随系统主题。配对取消、运行期间的禁用条件、端口校验和连接权限边界不变。

Android 13 及以上首次进入屏幕设置时推荐并预选内置 ADB。点「AI 操作手机」或确认 Agent 的屏幕授权请求时，如果用户还未选择过屏幕模式，会进入同一个向导。用户确认后才保存所选模式，并自行完成无线调试、配对和连接。退出向导时保留草稿，完成后才为本次请求检查屏幕权限。已经保存的模式会在之后的屏幕任务中继续使用。

引导一次只显示当前任务：模式、通知、Wi-Fi、开发者选项、无线调试、配对和连接分别处理；品牌说明、配对帮助和手动端口各自使用独立页面。开发者选项说明和连接辅助入口使用设置卡片，操作按钮固定在底部，小屏幕上的内容可滚动。

顶部共用编号步骤栏，当前步骤显示标题并高亮，步骤较多时可横向查看，并自动滚动到当前步骤。首次引导包含选择 Agent、连接 AI 服务和对应屏幕模式的步骤；单独进入屏幕设置时仅显示当前模式的步骤。编号按流程位置固定，已满足条件的步骤可跳过；辅助页面保留所属步骤高亮。已经推进过且仍满足条件的步骤可以点击回看，点击不执行授权、配对或连接。未完成的步骤保持禁用，继续时重新寻找第一个未满足的屏幕设置条件。首次引导中更换 Agent 会重置后续步骤的可回看状态。连接、配对或屏幕任务运行期间禁用步骤切换。

首次使用的登录优先流程、按品牌屏幕配置步骤和配对后一次连接见[首次使用与屏幕操作引导](setup-guide.md)。

步骤栏用勾标记已完成项、主题色高亮当前项、灰色显示未完成项。完成状态与是否允许点击分开处理：操作期间暂时禁用切换时，已完成项仍保留勾；辅助功能同时读出当前、完成或未完成状态。

## 权限与执行边界

四个 Agent CLI、Shell、HOME、网关和 Node 桥接保持原执行身份。权限仅授予独立屏幕工作进程。

内置 ADB 通过 APK 中的 `AdbScreenMain` 启动，root 通过 `RootScreenMain` 启动。两者复用同一个工作进程实现和本机 TCP 协议。地址只监听 127.0.0.1，每个连接使用随机 256 位临时令牌认证，令牌不进入 Agent、命令行、日志或持久存储。协议只暴露固定屏幕操作，不提供任意 shell 命令接口。输入参数保持结构化，启动包名严格校验。

工作进程只接受 UID 2000 或 0；root 模式额外要求连接身份为 0。依赖隐藏 API 的调用只发生在权限工作进程。`VirtualDisplay` 使用独立 ImageReader Surface 获取画面；UiAutomation 使用不压制已有无障碍服务的连接读取目标 displayId 的应用窗口。截图、节点、触摸和返回键都指向同一副屏，不读取默认活动窗口作为替代。

副屏输入法策略设为隐藏，文字通过目标节点的 `ACTION_SET_TEXT` 写入，避免将副屏键盘回退到主屏。有可编辑焦点时使用焦点；没有可编辑焦点时仅在存在唯一可见、可用输入框的情况下输入。密码输入拒绝，工作流的输入证据使用同一选择规则。

副屏 `home` 打开副屏内的应用列表，`recents` 打开当前副屏的现有任务列表，支持语义点击、坐标选择和滑动；返回键关闭导航面板或发送给副屏应用。两者不向系统发送 HOME/APP_SWITCH，不打开或操作主屏桌面/最近任务，也不声明具备厂商桌面的其他功能。应用列表是覆盖在副屏任务上方的导航面板，不会让底下的应用进入后台。任务切换再次核对 displayId，再在原副屏置前该任务，保留应用状态；`launch` 也优先恢复当前副屏已有任务。单任务应用若已在其他屏幕有任务，会明确拒绝启动以免把原任务拖到副屏。启动或切换后等待目标应用窗口出现，未观察到目标不报告成功。现有当前屏幕模式的系统桌面和最近任务行为保留。连接失效、超时、无窗口、不支持的语义及系统拒绝均返回失败，不回退到当前屏幕、不自动重试输入。

屏幕结果增加 `backend` 和 `displayId`，原有 screenshot resource、动作回执、取消与工作流协议继续使用。生成给 Agent 的技能写明本次后端。用户程序平台的 `screen.*` SDK 仍保持原有当前屏幕语义，不因聊天选择虚拟屏而获得提权能力。

## 当前限制

- 厂商 ROM、应用单实例/不可调整尺寸行为、跨应用跳转可能影响副屏可用性。部分应用可能自行跳到主屏；不能据此承诺任意应用都能隔离运行。
- Android 13 的焦点与输入法行为仍需设备验收，不能保证用户与 Agent 完全独立地同时输入。Android 14 以上启用副屏自身焦点标志。
- 受保护内容可能呈黑色；不绕过安全窗口保护。没有节点的自绘界面使用截图和坐标输入，未提供 OCR。
- 预览是按需刷新 JPEG，收起或预览不可见时停止刷新，不是视频流。
- 连接权限不是后台常驻保证；内置 ADB、su 后端或宿主被系统结束后需重新连接。

## 验证与复现

`ScreenChannelTest` 覆盖临时令牌握手、中文及 shell 元字符保持原值、root 身份拒绝、损坏响应关闭连接且不重试输入。`ScreenControlTest` 覆盖保存虚拟模式后不能借用现有无障碍权限回退到当前屏幕、切回当前模式恢复原有权限判断，以及启动参数校验。

独立真机探针使用生产工作进程，以 ADB shell 身份验证底层路径；它不能替代手机端内置 ADB 配对连接或真实 root 验收。已有手机可执行：

```sh
export JAVA_HOME=/path/to/jdk17
export ANDROID_HOME=/path/to/android-sdk
runtime/device-plugins/build_probe.sh
python3 runtime/device-plugins/probe_screen.py \
  --adb "$ANDROID_HOME/platform-tools/adb" \
  --jar runtime/device-plugins/build/screen-probe/worker.jar
```

构建脚本仅使用本机已有 Platform 36 和 Build Tools 35，不下载系统镜像。默认在副屏启动系统设置，检查窗口树、画面、非法输入拒绝、副屏应用/任务导航和关闭。专用测试 App 位于 `probe/`，APK 与测试签名仅在忽略的 build 目录生成。允许安装测试 App 的手机可安装 `build/screen-probe/probe.apk`，然后传入 `--package dev.mobby.screenprobe` 验证计数按钮、坐标点击、中文输入和滚动；结束后卸载测试 App。已安装 App 测试包时也可使用 `--package com.github.ytlog.mobby.android.test`，其按钮坐标由实际页面提供。

### 2026-11-05 副屏工作进程生命周期

参考 [Shizuku 的服务启动与断线处理](https://github.com/RikkaApps/Shizuku/blob/master/starter/src/main/java/moe/shizuku/starter/ServiceStarter.java)，mobby 通过现有的本机认证 socket 划分工作进程的生命周期。认证前的空连接、截断帧和无效 JSON 只关闭本次连接，工作进程在总启动时限内继续等待合法客户端。握手限制报文大小及每次尝试的总时间。认证后以该连接为副屏的所有者，连接结束即释放显示。ADB 和 root 分别要求工作进程 UID 为 2000 和 0。

创建或释放失败、连接超时、显示失效或返回错误显示 ID 时，宿主关闭该连接并清除预览，下一次使用需要重新连接。API 37 模拟器探针先复现了认证前断开导致合法连接失败，再验证空连接和无效 JSON 后仍可打开副屏、关闭后重开，以及断线后工作进程退出且无残留显示。

使用已有配对身份和手动连接端口，API 37 模拟器上的 mobby 正式内置 ADB 回归通过（27.448 秒）。Debug 与 AndroidTest 构建、相关单测和 lint 通过，419 项单测通过、2 项跳过。小米真机和 root 后端尚待复测。

### Android 版本与厂商覆盖

副屏最低支持 Android 13。AOSP 13 的任务查询接口有三个参数，14、15 和 16 的接口增加了显示 ID。工作进程在创建副屏前识别设备提供的签名，支持显示参数时直接查询副屏，两种签名都核对返回任务的实际显示 ID。只有确认签名不存在时才选择另一签名，系统拒绝请求时直接返回失败。[Android 13 接口](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-13.0.0_r1/core/java/android/app/IActivityTaskManager.aidl) · [Android 14 接口](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-14.0.0_r1/core/java/android/app/IActivityTaskManager.aidl) · [Android 16 接口](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-16.0.0_r1/core/java/android/app/IActivityTaskManager.aidl)

厂商验收分别检查无线配对、启动工作进程、创建副屏、输入及断线释放。Shizuku 的说明记录了 MIUI 通知回复和 ADB 权限差异、ColorOS 和 Flyme 的权限限制，以及 EMUI 和 Sony 的 USB 调试行为。它们是排查线索。小米 Android 13 有此前的内置 ADB 真机记录，最终版本的厂商覆盖仍待复测。Android 14–16 已核对源码，尚无本轮设备结果。[Shizuku 厂商说明](https://shizuku.rikka.app/guide/setup/#faq)

本轮 Debug 构建及设备插件单测通过，覆盖三参数、四参数及缺失签名。使用更新后的 APK，API 37 模拟器内置 ADB 正式副屏回归通过（20.33 秒）。
