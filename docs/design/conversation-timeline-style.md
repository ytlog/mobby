# 对话时间线样式

用户反馈对话页观感差。对照真机长对话截图，根因不在玻璃控件，而在时间线本身：过程信息与回复同等醒目，把正文淹没。本文记录修正后的样式约定，交互规范仍以 [Android 对话 UI 评审稿](conversation-ui-review.html) 为准，顶部栏与输入框的材质见 [聊天页玻璃控件](glass-controls.md)，本轮未改动它们。

## 层次

一轮对话的阅读重点依次是：用户消息和回复正文、需要处理的事项、已结束的过程。

- **回复正文**是页面主角：16sp、行高 26sp，不加字距。
- **两段回复之间已结束的过程合并成一行摘要**，如“已完成 8 个步骤”，文字与正文左对齐，不带图标。展开后按发生顺序列出步骤和设备操作（`timelineEntries`）。
- **卡片只在有内容要看时出现**：展开后的设备操作、代码块、权限请求、带错误信息的失败。
- **用户主动停止或排队**是一行普通状态，不用警告色。
- **复制和分享放在回合末尾**，不夹在回合中间。
- 运行中只展开当前所在的步骤组，较早的组在有了后续内容后收起。

## 真实状态

合并不能隐藏需要看到的结果：

- 正在运行、等待回应、结果不是明确成功（失败、待确认、部分完成、已停止）的设备操作，以及有照片预览的操作，都单独成行，不进入摘要。
- 摘要只说明自己的步骤：全部成功显示“已完成 N 个步骤”；部分失败显示“11 个步骤 · 1 个失败”，避免读成全部失败；全部失败显示“失败 · N 个步骤”；结果未确认只显示“N 个步骤”，不声称成功。
- 回合如何结束由状态行说明。只有失败且没有错误信息、因而没有状态行时，最后一组才显示“失败”。此前回合停止后每一组都显示“已停止”，与事实不符。
- 合并后条目减少，已保存的阅读位置和搜索结果可能指向已折叠的行，这些键会解析到所在的摘要（`timelineKeyAliases`）。
- 失败信息保留全文和“恢复到输入框”。

## 间距

列表不再使用统一的 16dp 间距，由前后两项的类型决定（`timelineGap`）：

| 位置 | 间距 |
| --- | --- |
| 过程行之间 | 0dp，行高 36dp 已留白 |
| 过程行与其他内容之间 | 4dp |
| 复制和分享之前 | 0dp，按钮自带留白 |
| 用户消息之后 | 16dp |
| 其他内容之间 | 12dp |
| 新一轮的用户消息之前 | 28dp |

用户气泡左侧至少留 48dp，避免长消息贴满整屏。选中上下文气泡时，时间线底部渐隐加长，滚到气泡下方的文字淡出，不与气泡相撞。

## 主题

- 中文正文不使用 Material 为拉丁文设计的字距，`MobbyTypography` 统一设为 0。所有使用对话组件的 `MaterialTheme` 都传入它。
- 浅色主题按用户选择使用“暖纸”配色，覆盖对话页、抽屉、面板、菜单、设置页和普通玻璃，避免切页时冷暖割裂：画布 `#FBFAF7`、页面 `#F6F4EF`、卡片 `#FFFDF9`、正文与控件 `#2C2A26`、次要文字 `#736E63`、占位文字 `#8C8779`、强调色赤陶 `#B4552F`（取代对比度只有 3.7:1 的亮蓝）。正文对比度不低于 12:1，次要文字、强调色和警示色不低于 4.5:1，由测试约束。深色配色未调整。
- 过程摘要和状态行用 13sp、12dp 箭头、14dp 图标，与 16sp 正文拉开层级。行内代码缩到 0.85em，底色减淡；加粗从 Bold 改为 SemiBold，避免中文发黑发重。
- 配色方案补齐容器色和表面色。此前未设置的字段回退到 Material 默认紫色，这是上下文气泡发紫的原因。气泡仍是原 InputChip，位置和尺寸不变，只修正颜色。
- 对话画布上的卡片统一用 `conversationCardColor()`。此前浅色卡片与白色画布同色，代码块没有边界。
- 系统栏透明，由各页面背景延伸到状态栏下方，消除状态栏与页面之间的色差。
- 代码块显示时去掉末尾空行，复制仍保留原文。
- 屏幕结果展开后的控件树依赖缩进和长行，按等宽字体显示，在卡片内横向和纵向滚动，高度上限 200dp。

## 弹窗

所有弹窗共用 `ModalSurfaces.kt`，不在各页面单独设置样式：

- **底部弹窗**用 `AppSheet`：相同底色、28dp 顶部圆角、直接完全展开，大屏上对齐所在页面的列。内容用 `SheetBody`，超高时可滚动。
- **弹窗里的选项**用 `SheetRow`：无底色，图标、标题、说明和箭头布局相同，行高至少 60dp，行间没有额外间距，读作一个列表。此前技能弹窗每行至少 76dp 且带 10dp 间隔，首页弹窗每行也多 8dp。
- **居中弹窗**用同包的 `AlertDialog`：相同底色、24dp 圆角和 18sp 半粗标题，避免漏设样式时回退到 Material 默认表面。调用时不能传它不接受的参数，否则 Kotlin 会静默选中 Material 原版。

抽屉左上角使用单色应用图标加 18sp 半粗的 mobby，颜色与正文相同，尺寸不超过周围控件。彩色图标是蓝色，与暖纸配色不搭，因此不在这里使用。

- 第一轮先添加回归测试并确认失败 8 项，再修复；真机看过后认为过程仍占据过多版面，第二轮确认 5 项失败后合并成摘要；真实数据又暴露“失败 · 11 个步骤”的误读，确认失败后修正。
- JBR 21 下 `:app:assembleDebug`、`:app:testDebugUnitTest`（349 项）、`:termux-core:testDebugUnitTest`（32 项）、`:app:lintDebug` 通过。
- 版本号 109 覆盖安装到手机，未清除数据。在真实长对话的浅色主题下核对顶部、中部和底部截图：摘要计数、部分失败、结果待确认、停止状态、回合末尾的操作按钮、气泡处的文字淡出均显示正确，状态栏与页面无色差。
- 用户反馈正文黑色与其他文字不搭后，调整文字色和字号，再次核对浅色真机截图，并展开摘要和屏幕详情确认显示正常，核对后恢复收起。
- 用户比较四套配色后选择暖纸。JBR 21 下构建、App 351 项与 termux-core 32 项单测、lint 通过；覆盖安装后在浅色真机核对对话页、抽屉、加号面板和设置页，设置页状态栏无色差。
- 统一弹窗后，JBR 21 下构建、App 359 项与 termux-core 32 项单测、lint 通过。真机浅色核对首页加号弹窗、技能添加弹窗和重命名弹窗（取消，未保存）以及抽屉左上角。其他居中弹窗和阅读面板走同一组件，未逐一打开。
- 深色主题只在合并摘要之前用夹具渲染检查过，之后的摘要、字号和代码样式未再查看，也未在真机切换，以免改动用户外观设置。
- 未验证：运行中实时滚动与帧率、折叠屏与平板、大字体，以及未逐一打开的其他页面在暖纸配色下的效果。
