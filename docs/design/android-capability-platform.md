# Android 能力基座与自动化程序平台设计

状态：设计提案。日期：2026-10-24。

mobby 向 AI 编写的程序提供 Android 能力、事件订阅、运行环境和程序管理。用户可以让 AI 编写一个程序，安装并启用后，由手机事件或时间条件触发执行，不再依赖某次聊天任务持续运行。跳过开屏广告是首个验证场景，后续可扩展到文件处理、通知协作、设备连接和个人自动化。

本方案定义完整的产品能力面、统一契约和实施顺序。目录中的候选能力不是交付承诺，也不改变 [AGENTS.md](../../AGENTS.md) 的现有边界。具体接口必须按 Android 版本、设备硬件、系统授权、平台角色和真实验收结果报告可用性。

## 目标与范围

### 用户使用方式

1. 用户描述需求，例如“在我选择的几个应用里自动跳过开屏广告”。
2. AI 根据基座实际提供的能力目录编写程序包，调用本地校验和试运行接口。
3. 程序中心展示代码或规则、目标应用、事件、所需能力和预期行为。
4. 用户配置并启用程序，授予明确范围内的持续执行权限。
5. Android 端持久保存程序、配置和订阅，在条件满足时执行。
6. 用户查看触发记录、真实动作和结果，随时暂停、停止或删除程序。

“程序已启用”和“当前可以工作”分别呈现。权限被撤销、无障碍服务断开、目标设备离线时，程序不能继续显示为正常执行。

### 设计原则

- 手机能力统一由宿主登记和执行；程序不能通过一个通用接口反射调用任意 Android API。
- 事件在 Android 端过滤并按实际交付语义分发；程序无需持续轮询所有系统状态。
- 高频、短时、确定性操作使用本地规则；复杂业务使用 Node；AI 推理作为显式可选步骤。
- 持久订阅独立于 JavaScript 进程和聊天 run，进程退出不等于删除程序。
- 现有聊天执行路径继续有效；新增程序平台共用设备执行器，不另写一套屏幕或短信实现。
- 系统权限、程序授权和本次运行条件分开检查。取消、失败、超时和效果不明如实传递。
- 当前任意代码执行以应用 UID 和 SELinux 沙箱为边界，不把程序清单、目录或令牌宣传为程序间安全隔离。

“已有基础”只表示存在对应代码路径。新增动作、持续会话、事件来源和机型兼容必须分别验收，不能由原有单次调用推断。

## 统一能力模型

### 五类能力

| 类型 | 含义 | 示例 |
| --- | --- | --- |
| query | 读取当前状态或数据 | 电量、当前窗口、日历列表 |
| command | 执行一次可能产生副作用的操作 | 点击、发送短信、写文件 |
| event | 接收状态或数据变化提示 | 窗口变化、充电、通知发布 |
| session | 开始、持续、关闭一组资源 | 录音、蓝牙连接、持续定位 |
| handoff | 交给系统或用户继续完成 | 文件选择器、录屏授权、打开拨号界面 |

命名采用稳定领域 ID，例如 `screen.snapshot`、`screen.click`、`ui.changed`、`audio.recording`。该 ID 与现有 `plugin:device:` 草稿引用分别承担接口身份和用户选择身份，不能静默替换旧引用的含义。

### 能力描述

每个已实现能力由宿主注册以下信息，并用于生成 SDK、文档、校验和界面摘要：

| 字段 | 用途 |
| --- | --- |
| id、version、kind | 稳定身份、契约版本与五类能力类型 |
| inputSchema、outputSchema | 参数、结果、枚举和资源引用结构 |
| implementation | 实现是否随宿主打包；未实现项不伪造处理器 |
| prerequisites | 最低版本、硬件、平台服务、角色、权限、系统白名单 |
| scopeSchema | 可限制的应用、目录、数据源、外设等范围 |
| executionConditions | 前台、解锁、用户交接、持续会话等条件 |
| sideEffects | 是否发送、修改、删除或控制其他应用 |
| interaction | 无交接、宿主用户输入、系统同意或现有专项确认 |
| cancellation、timeout | 取消是否可中止已派发操作、期限与未知结果处理 |
| idempotency | 平台去重范围及底层是否支持幂等 |
| limits | 大小、频率、并发、持续时间与资源预算 |
| delivery | 事件是否持久、可合并、可重放、如何过期 |
| availability | 当前系统授权、程序授权、来源连接和不可用原因 |

可用性不是单个布尔值。至少区分“未实现、设备不支持、缺少系统授权、程序未获授权、来源未连接、需要用户交接、当前条件不满足、当前可用”。

### 实际授权范围

有效调用范围是以下集合的交集：

```text
宿主实际实现
∩ 当前设备和平台支持
∩ 系统当前授权
∩ 程序清单请求
∩ 用户授予程序的范围
∩ 本次任务允许范围
∩ 当前执行条件
```

清单是请求，不能自行授予权限。系统危险权限按应用 UID 授予；程序级限制由宿主 API 执行，任意同 UID 原生代码不受这些 API 限制的强制隔离。

## Android 能力目录

下列目录覆盖产品可扩展的主要能力面，不逐条复制 Android 全部 API。表中“候选”均需要独立实现与验收；“条件候选”还需要硬件、角色、系统服务或额外授权。现有明确排除项集中列在本节末尾。

### 屏幕与应用交互

| 能力 | 查询或动作 | 事件与条件 | 现状或范围 |
| --- | --- | --- | --- |
| 界面读取 | 窗口树、文字、描述、角色、边界 | 窗口和内容变化；系统允许暴露的节点 | 已有基础，事件待做 |
| 控件操作 | 点击、输入、长按、选择、滚动 | 目标消失、完成、取消 | 点击和输入已有；其余候选 |
| 坐标与手势 | 点按、滑动、拖动、多点手势 | 系统完成或取消回调 | 点按已有；其余候选 |
| 系统导航 | 返回、主页、最近任务 | 依系统支持逐项报告 | 已有基础 |
| 截图 | 获取允许读取的显示内容 | 保护窗口、频率与资源限制 | 已有基础 |
| 录屏 | 捕获选定显示或应用内容 | MediaProjection 用户同意及会话管理 | 条件候选 |
| 前台窗口观察 | 应用包名、窗口身份、显示器 | 只代表观察到的窗口，不能当作进程冷启动 | 待接入 |
| 应用入口 | 打开指定应用或公开链接 | 目标可访问，遵守后台启动限制 | 候选 |
| 应用公开功能 | App Functions 参数和调用 | 平台、授权、白名单、目标函数均支持 | 已有基础，成功调用待验收 |
| 分享与文件打开 | 分享文本、图片、文档，系统打开 | 用户选择目标、完成或取消 | 候选 |
| 剪贴板 | 读取、写入、清除 | 不提供无条件全局后台读取和监听 | 前台读写已有基础 |
| 选择器 | 文件、照片、联系人等系统选择 | 用户选择或取消，取得范围有限的引用 | 目录已有，其余候选 |

无障碍事件及操作遵循 [Android 无障碍服务](https://developer.android.com/guide/topics/ui/accessibility/service) 的配置和系统授权。录屏与现有无障碍截图是两类能力，MediaProjection 按会话取得用户同意，见 [MediaProjection](https://developer.android.com/media/grow/media-projection)。剪贴板访问限制见 [Android 10 隐私变化](https://developer.android.com/about/versions/10/privacy/changes#clipboard-data)。

### 通信与个人信息

| 能力 | 查询或动作 | 事件与条件 | 现状或范围 |
| --- | --- | --- | --- |

| 联系人 | 查询、创建、修改、删除、选择 | 数据变化后重新查询 | 读写已有，事件和查询增强待做 |
| 日历 | 查询、创建、修改、删除 | 数据变化；程序到期调度另行登记 | 读写已有，事件待做 |
| 通知读取 | 来源、分组、允许提供的内容 | 发布、更新、移除，敏感内容可能受限 | 候选，需要通知访问授权 |
| 通知动作 | 清除、执行公开按钮、直接回复 | 只允许通知实际提供的动作，独立授权 | 候选 |
| 本应用通知 | 状态、提醒、停止和操作按钮 | 用户点击、通知权限或渠道关闭 | 宿主已有基础，程序接口待做 |
| 电话交接 | 打开拨号页面 | 用户继续操作 | 候选 |
| 直接拨号 | 系统允许的电话调用 | CALL_PHONE 等条件，独立授权 | 现有设计的后续候选 |
| 通话状态和记录 | 系统允许提供的状态与记录 | 按版本、权限和角色核实 | 后续条件候选，不承诺接听或录音 |
| 本机号码 | 系统允许提供的号码 | 可能缺失，不能推测 | 现有设计的后续候选 |
| 邮件和即时通信 | 公开 API、连接器或分享交接 | 服务账户与目标接口授权 | 集成候选，不访问应用私有数据库 |

通知授权不保证完整敏感正文，例如 Android 15 对不受信任的通知监听器限制验证码内容，见 [Android 15 行为变化](https://developer.android.com/about/versions/15/behavior-changes-all)。通信接口的系统授权、默认角色与发布渠道要求必须在实际接入时分别核实。

## 架构与模块职责

### 模块组合

| 模块 | 职责 | 依赖方向 |
| --- | --- | --- |
| 现有 `:device-plugins` | 设备目录、系统授权检查、实际动作和事件适配器 | 不依赖程序管理和对话 UI |
| 拟新增 `:automation` | 包管理、授权、订阅、调度、规则、任务、持久化、HTTP 与 Node 适配 | 依赖设备能力和必要的 runtime API |
| 现有 runtime | 终端、Agent 和既有设备桥接 | 不反向依赖自动化 UI；提供必要执行端口 |
| `:app` | 组合、程序中心、配置、运行记录、入口和通知 | 依赖上述模块，以回调或端口绑定 |
| 现有本地模型服务 | 独立模型管理与推理 HTTP 服务 | 不依赖自动化平台 |

首版在 `:automation` 内按 package 划分职责，确有跨模块复用时再提取小型纯协议模块。程序管理器不能直接依赖对话 ViewModel 或修改现有会话状态。

新增源码沿用 `com.github.ytlog.mobby.android` 前缀及独立子包，不更改 applicationId 或 `mobby.gateway` Keystore 别名。

### 运行进程

首版 Android 管理逻辑、HTTP 入口、规则与设备适配在现有应用进程组合，Node 使用现有应用 UID 下的子进程。按任务和事件来源管理生命周期，不创建一个声称永久存活的万能后台 Service。

需要用户可见持续工作的能力，按实际用途选择合适的前台服务及启动条件；其他工作使用平台调度或当前事件来源。是否为自动化另建专用进程，可在实测资源和故障边界后决定；独立进程与同 UID 本身不提供不可信程序隔离。

本地模型仍在 `:local_model` 进程，通过鉴权 HTTP 进行业务通信。Intent 仅启动组件，不通过 Binder、AIDL 或跨进程 Kotlin 调用传递模型业务。

### 统一设备执行入口

现有聊天桥接和新增程序 API 都转换为内部类型化设备请求，经同一个授权检查、动作协调、执行器和结果端口处理。需要时在有限范围内提取执行上下文，将聊天 run 与程序 task 分别映射进去。

新入口不伪造一个永久聊天 run，也不把聊天令牌延长为程序令牌。现有 `mobby.device/1` 请求、去重和关闭语义保持不变；程序平台拥有自己的持久任务身份。

### 三种执行方式

| 方式 | 用途 | 生命周期与限制 |
| --- | --- | --- |
| Kotlin 声明式规则 | 跳广告、有限条件匹配、简单动作 | 无任意代码、无网络和无限循环；有节点数、深度、次数与期限限制 |
| Node 短任务 | 文件处理、多步业务、数据和联网 | 事件触发、有限并发、可取消，完成后退出 |
| 显式持续会话 | 设备连接、音频、持续流 | 用户发起，管理资源租约和停止入口，满足对应后台规则 |

声明式规则和脚本使用同一能力执行器。规则只负责条件和编排，不维护另一套点击逻辑。高频无障碍回调不等待 Node、模型或复杂树遍历；回调只提取必要元数据、合并并安排有界工作，遵守平台线程要求。

## 程序包与生命周期

### 包结构

```text
skip-splash/
  manifest.json
  rules.json
  main.js
  ui.json
  assets/
  README.md
```

清单指定一个必须存在的实际入口，未使用的规则、脚本和界面文件无需打包。脚本执行器交付 JavaScript；TypeScript 在打包时转换，不要求手机运行时安装构建工具。依赖应锁定并打包或明确安装，启用程序不隐式执行依赖安装钩子。

安装校验覆盖包大小、文件数量、归一化相对路径、重复路径、符号链接、入口存在性、Schema、宿主版本与能力引用。程序包是用户信任并安装的代码，不通过解压写入宿主配置、其他程序或工作区。

### 清单示例

以下字段属于拟议 `mobby.program/1` 契约，包名仅为示例：

```json
{
  "schema": "mobby.program/1",
  "id": "skip-splash",
  "version": "1.0.0",
  "name": "跳过开屏广告",
  "execution": {
    "kind": "rules",
    "entry": "rules.json"
  },
  "requestedCapabilities": [
    {"id": "screen.observe", "scope": {"packages": ["com.example.target"]}},
    {"id": "screen.click", "scope": {"packages": ["com.example.target"]}}
  ],
  "subscriptions": [
    {
      "id": "target-ui",
      "event": "ui.changed",
      "filter": {"packages": ["com.example.target"]},
      "handler": "skip-splash"
    }
  ]
}
```

包内订阅声明由安装器登记为程序资源。运行时也可通过 API 增删订阅，但不能超过清单及实际授权范围。持久订阅由 Android 保存；`events.on` 一类内存回调只能消费已登记的事件，不能承担持久注册。

### 程序和任务状态

程序安装状态、用户启用意愿和运行可用性分别保存：

- 安装状态：已安装、待更新、删除中。
- 用户状态：已启用、已暂停、已停用。
- 可用性：可工作、缺权限、来源断开、需用户交接、条件受限。

一次触发创建一个 task，具有排队、运行、等待用户、请求取消和终态。终态至少区分成功、失败、取消、超时、中断、结果不明，不用“进程退出”直接推断业务成功。

暂停停止接收新触发，并按用户操作选择是否停止当前任务；“停止全部”必须同时停止待运行任务、后续动作和可关闭会话。已经交给系统的手势或短信可能不能撤回，应保留实际回执与不确定副作用。

### 更新与卸载

更新先校验新包，当前任务固定原版本；新订阅切换到新版本时使用世代号，旧事件不能调用新入口。扩大能力、目标范围、事件来源或后台执行范围时，需要授予新增部分。

回退版本也必须重新验证宿主支持和当前授权，不能恢复旧版本曾持有但已经撤销的权限。用户配置和数据独立于不可变程序包；不满足新版本数据结构时明确阻止启用，不静默清空用户数据。

卸载注销订阅、取消任务、关闭会话、撤销程序授权与令牌。程序私有数据提供明确删除选择；共享工作区和用户授权目录内的数据不随程序卸载删除。

## 事件系统与时间调度

### 来源目录

| 来源 | 典型事件 | 实际交付说明 |
| --- | --- | --- |
| 无障碍 | 窗口、内容、焦点等变化 | 瞬时观察，可合并；不代表应用进程启动 |
| 通知监听 | 发布、更新、移除 | 按系统允许内容交付，连接恢复后重新核对 |
| 数据提供器 | 联系人、日历、媒体变化 | 通常是重新查询提示，不保证完整变更日志 |
| 系统广播和回调 | 充电、网络、屏幕、时间、可见包变化 | 版本、注册方式和后台状态影响交付 |
| 传感器 | 采样、阈值或派生事件 | 仅活跃会话与允许采样范围内有效 |
| 外设会话 | 连接、断开、数据、设备变化 | 绑定 sessionId 和授权设备 |
| 用户入口 | 程序按钮、分享、快捷方式、通知动作 | 参数和授权由宿主校验，不能相信外部 Intent 自报身份 |
| 平台调度 | 单次、周期、日历时间到期 | 明确精度、约束、错过策略 |
| 程序内部 | 任务完成、自定义事件、文件变化 | 明确发布者、接收者与数据权限 |
| 外部服务 | 已授权连接的消息、Webhook | 独立连接器；loopback 端口默认不接受互联网入站 |

Android 广播可能延迟或合并，见 [广播概览](https://developer.android.com/develop/background-work/background-tasks/broadcasts)。来源未声明可恢复时，平台不能承诺补齐进程停止期间的所有事件。

### 事件信封

事件至少包含 `schema`、`eventId`、`source`、`type`、`sourceGeneration`、`observedAt`、`expiresAt`、`scope`、`payload` 和可选 `causationId`。身份由来源适配器生成，不接受程序冒充系统来源。

瞬时事件以过期时间与来源世代判断有效性；屏幕动作仍重新读取当前窗口，不把事件里的旧节点作为目标。单调时间用于当前启动期间的期限，持久日历调度使用带时区的墙上时间；设备重启后废弃旧的瞬时期限和观察。

### 订阅与过滤

宿主持久保存 `subscriptionId`、programId、包版本、handler、事件类型、范围、过滤表达式、交付策略和授权修订号。

先在 Android 端按类型与范围过滤，再做合并、去抖、冷却、队列和配额检查，最后创建任务。表达式采用有界 AST，支持与、或、比较、存在、阈值和时间窗口；不执行任意脚本或无界正则。

系统监听配置采用所有有效订阅所需范围的并集，但每个程序只收到其授权范围内的投影。暂停、注销或撤权后重新计算来源范围，没有消费者时释放可释放的监听与采样资源。

### 交付语义

| 类别 | 持久化与恢复 | 消费规则 |
| --- | --- | --- |
| 界面和高频状态 | 不保存整页或持续采样流；可保存必要诊断 | 只保留新鲜状态，允许合并和丢弃过期项 |
| 已持久接收的业务触发 | 保存接收记录、消费状态和任务关联 | 在保留窗口内可重投，按事件与处理入口去重 |
| 变化提示 | 恢复后执行重新查询 | 不推断每一条底层新增、修改或删除 |
| 会话事件 | 持久保存会话身份和终止事实 | 断线或恢复后重新建立会话，不伪造原连接持续存在 |
| 用户输入 | 保存等待点及消费记录 | 绑定任务、版本与 revision，一次消费 |

去重不等于对外副作用恰好一次。对系统或外部服务未提供幂等保障的操作，崩溃恢复后不能盲目重发。

### 时间调度

调度登记时间类型、时区、约束、允许延迟、错过策略、结束条件和总执行次数。错过策略包括跳过、合并补一次、有限补执行，默认不能补发过期屏幕动作。

可延期后台工作使用 WorkManager；周期最短 15 分钟且受系统优化影响，见 [WorkRequest](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)。满足用途和授权条件的精确定时使用 AlarmManager，见 [闹钟调度](https://developer.android.com/develop/background-work/services/alarms)。秒级 UI 反应使用有效事件来源，不用循环唤醒调度模拟实时系统。

开机恢复仅重建系统允许恢复的调度和监听。用户强制停止、设备锁定或系统限制时，保持准确状态，不绕过停止语义。

## 授权与代码信任

### 两种授权生命周期

| 场景 | 授权生命周期 |
| --- | --- |
| 聊天 Agent 设备插件 | 继续按加入草稿与本轮能力执行，桥接关闭即失效 |
| 安装程序 | 用户独立授予程序、范围、触发方式和持续期限，直至暂停、撤销或到期 |

持续程序授权不会从某次聊天自动继承。AI 可以生成、校验和准备程序，安装与启用是程序中心可审阅的明确操作；用户已经明确授权安装或启用具体程序时，不额外增加重复确认。

读、写、发送、删除和控制分别声明；作用域包含目标应用、目录、记录集合或外设。系统权限不足时由用户可见界面申请，不在事件回调中反复弹窗。

现有 App Functions 的用户确认，以及相机和麦克风采集确认保持原行为。持续程序授权不能静默取消系统要求或已有专项确认。

### 撤权与修订

每个任务和待派发操作携带授权修订号。执行前检查最新授权；撤销时先使授权失效，再注销订阅、关闭会话和取消队列，避免已入队动作继续派发。

程序包自行修改请求不改变实际授权；新申请、新事件和扩大过滤范围都要通过同一授权管理入口。重试、子任务、程序间调用与 AI 步骤不得扩大范围。

### 受信任脚本的实际边界

Node、Shell 和现有 Agent 与应用共享 UID。目录配额、API 白名单、网络域名范围和任务令牌可以管理经平台接口发生的行为，但不能强制阻止任意同 UID 代码绕过 SDK、读取可访问文件或另开网络连接。

首版明确支持用户信任的本地脚本和不含任意代码的规则。若未来运行不可信第三方程序，需要另行选择隔离执行环境，并验证文件、网络、进程、凭据和系统权限边界；不将普通独立进程视为解决方案。

### 凭据与外部数据

网关密钥和真实用户配置只保存在设备加密存储。程序包、示例、测试、Git、诊断日志不包含实际凭据。凭据 API 优先提供用途受限的引用和宿主代用，不提供通用明文导出。

网页、通知、屏幕文字、文件和发布方功能描述属于外部数据，不能替代系统指令或触发自动授权扩张。将数据交给 AI 时，保留来源和任务边界。

现有 App 内 Agent 模型请求继续经本地 Node 桥接，由 Android 网络栈联网；Pi、Codex、OpenCode 仅使用 Responses，Claude Code 仅使用 Messages，远端网关保持原生协议透传。现有各 Agent 的工具审批和执行边界保持项目决定；自动化程序调用 Agent 时不能改用 bypass、提权或增加未授权的工具范围。

## 本地 API 与 SDK

### 传输与身份

拟议程序主入口使用绑定 `127.0.0.1` 的鉴权 HTTP API；任务状态事件优先 SSE，需要双向持续协议时再使用 WebSocket。默认不监听局域网或互联网，不为 Webhook 打开公网端口。

端口按宿主实际分配并通过受控启动信息交给程序；每个运行实例使用范围受限、可撤销的临时凭据。身份、程序版本和任务上下文从宿主认证绑定，不相信 body 中自报的 programId。

对浏览器来源执行 Origin、Host 与 CORS 校验，令牌不进入 URL、日志或程序包。现有聊天 JSON 行桥接保持原协议，不在原端口自动识别并混用 HTTP。

### 资源接口

| 入口 | 用途与调用者 |
| --- | --- |
| `/v1/capabilities` | 查询调用者可见的能力、Schema 和实际可用状态 |
| `/v1/programs` | 安装、更新、授权和启停；仅宿主管理身份，程序普通身份不能管理其他程序 |
| `/v1/subscriptions` | 当前程序授权范围内的登记、查询和注销 |
| `/v1/tasks` | 当前任务、允许的子任务、状态与取消 |
| `/v1/operations` | 提交能力调用、查询原操作、取得回执 |
| `/v1/resources` | 当前范围内的资源元数据和内容导出 |
| `/v1/sessions` | 开始、查询、关闭当前程序允许的持续会话 |
| `/v1/events` | 当前运行实例实际允许消费的事件流 |

SDK 隐藏传输细节，但不隐藏用户交接、异步终态和失败。以下为拟议 JavaScript 用法：

```javascript
const capabilities = await mobby.capabilities.list();
const task = await mobby.tasks.current();
const entries = await mobby.calendar.list({ start, end });
await mobby.state.set("lastCheckedAt", Date.now());
await mobby.notifications.show({ title: "处理完成" });
```

### 请求结果与错误

程序平台使用独立版本化契约，请求包含 schema、requestId、能力 ID、参数和期限。解析器拒绝未知版本、未知参数、越权字段与不支持的语义，不静默丢字段。

宿主按任务、requestId 和参数指纹去重，并将派发前记录持久化。重连查询原 operationId，不能换 requestId 规避效果不明的旧操作。去重保留期限需公开，超出期限时不能宣称仍有幂等保障。

错误至少区分 `UNSUPPORTED`、`PERMISSION_DENIED`、`SCOPE_DENIED`、`SOURCE_DISCONNECTED`、`CONDITION_UNMET`、`USER_INTERACTION_REQUIRED`、`TARGET_NOT_UNIQUE`、`STALE_OBSERVATION`、`REQUEST_CONFLICT`、`RESOURCE_MISSING`、`CANCELLED`、`TIMEOUT`、`EFFECT_UNKNOWN`。

操作事实分别保存受理、派发、执行器回执与目标验证。任务成功取决于对应能力或程序声明的完成条件；未要求业务验证的纯查询可直接完成，需要页面或外部效果验证的任务不得用进程退出码替代。

文件、图片和音频使用 resourceRef，包含归属、类型、大小和保留属性。持久附件与可淘汰缓存分别管理；引用失效返回资源缺失，不偷偷重新采集。

## 状态数据与恢复

### 数据所有权

| 数据 | 所有者与保存方式 |
| --- | --- |
| 不可变包版本与校验记录 | 安装器，应用私有包目录 |
| 用户启用意愿和授权 | 宿主管理端，私有持久存储 |
| 配置、订阅和调度 | 程序平台，绑定包版本和授权修订 |
| task、operation、消费与去重记录 | 程序平台，派发前写入 |
| 程序业务数据 | 程序级数据区，与包目录分离 |
| 凭据 | 设备加密存储，业务记录只保存引用 |
| 持久附件与截图缓存 | 资源管理器，分别管理归属与淘汰 |

建议新增独立开发数据库 `automation.db`，由程序平台单一拥有，不让脚本直接修改宿主调度和回执表。程序业务 SQLite 是另一类数据。

开发阶段宿主数据库结构变化按项目规则清空对应开发数据库并重建，不编写历史迁移和兼容测试；保留 SharedPreferences、HOME 和工作区。持久引用不可恢复时标记为需重新绑定，不伪造授权。

### 恢复规则

1. 恢复安装信息、用户状态、授权、订阅和可恢复调度。
2. 对尚未派发的任务重新核对期限与范围；过期 UI 任务丢弃。
3. 对已派发任务查询执行事实，缺少可靠结果则标记中断或效果不明。
4. 不自动重复可能产生副作用的动作。
5. 关闭失效资源租约，以新 sessionId 重新建立允许恢复的会话。
6. 按来源支持重新查询当前状态，明确记录观察缺口。

## 并发性能与运行协调

### 屏幕协调

所有调用者共用屏幕动作协调器，包括聊天 Agent、规则、脚本和工作流。首版只支持经过验收的当前显示路径；多显示器或多用户范围未实现时明确拒绝。

用户当前的交互任务优先于后台规则。切换占用者时取消未派发动作，已经交给系统的手势等待实际回调后再交接，不把暂停当作已撤回动作。操作前重新读取窗口和唯一目标，不跨动作缓存节点。

现有悬浮球避让、通知停止和单次屏幕操作恢复继续复用。长期订阅本身不调用现有每轮 `stay()`，不因此保持屏幕常亮、不持有永久唤醒锁，也不解除锁屏。

### 其他资源

相机、麦克风、外设连接、持续定位等使用可关闭租约，绑定程序、任务与会话。取消、撤权、来源断开和程序删除都走统一清理；无法中止的操作保留事实。

Node 短任务按程序与全局限制并发；输入输出有大小上限与背压。宿主 API 的队列、资源和网络预算可以计量，任意脚本的绝对 CPU、内存和网络硬限制需要根据实际 OS 边界验证，不仅靠 JavaScript 定时器声称实现。

### 性能策略

- 订阅先按目标应用和事件类型过滤，避免全局读取控件树和截图。
- 界面变化合并后按需读取，只对有效观察窗口执行匹配。
- 规则匹配限制树深度、节点数、表达式复杂度、动作次数和时间。
- 日常规则不启动模型，普通事件不默认附带整页截图。
- 调度和日志批量策略不能延后必须在派发前完成的安全与去重记录。
- 具体耗时、频率和容量默认值通过已有手机测量后确定；不预先承诺固定毫秒级反应。

## 跳过开屏广告的端到端设计

### 授权与规则

程序请求观察和点击用户选定应用，不请求所有应用、不读取其他插件数据、不需要日常模型推理。每个应用有独立规则，包含包名、候选入口、开屏页面特征、唯一目标、动作和后置验证。

“观察到应用进入前台”只能开启候选观察阶段，不能当作冷启动事实。“跳过”文字也不能单独证明是广告，需要结合该应用的控件 ID、角色、可点击性、位置或其他页面条件。匹配不足时停止，不自动改成坐标兜底。

### 执行过程

1. 观察到目标窗口，建立有限时长、有限动作次数的候选观察阶段。
2. 合并该阶段内的内容变化并读取当前页面；只观察模式只报告命中与拟执行动作。
3. 同时满足目标应用、开屏页面特征和唯一跳过控件条件。
4. 协调器取得屏幕执行权，再次检查当前窗口、授权和目标。
5. 调用共用执行器执行一次点击，保存系统实际回执。
6. 在规则允许的时间内观察后置条件，分别记录点击执行和跳过验证。
7. 成功、超时、切换应用、锁屏、撤权、停止或结果不明时结束本次尝试。

程序自己的点击导致的新事件携带可追踪因果关系，并受本次观察阶段的动作上限与冷却控制；系统事件无法可靠归因时仍靠状态机防止重复点击。

无法提供足够无障碍控件的应用可报告不支持。OCR 或图像匹配若后续引入，作为独立能力和证据重新验收，不把模型识别当作天然可靠的按钮定位。

### 真机验收

- 至少一个用户指定的真实应用可命中正确开屏页面并完成验证。
- 同一应用教程或表单出现“跳过”时，不满足开屏条件就不点击。
- 无目标、多目标、延迟出现、离开应用和界面切换均不会盲点。
- 点击回执成功但后置条件未满足时，不显示“广告已跳过”。
- 与聊天屏幕操作并发时按协调策略暂停，不互相抢点。
- 用户停止、无障碍断开、通知停止入口失效或权限撤销后不再派发新动作。
- 屏幕熄灭后不为等待广告而持续唤醒或解锁。
- 进程恢复不重放旧窗口事件，也不重复效果不明的点击。

## 程序中心与 AI 开发流程

### 页面

| 页面 | 内容 |
| --- | --- |
| 程序列表 | 名称、用户启用状态、实际可用性、最近结果 |
| 概览 | 用途、来源、版本、目标范围、启动暂停停止 |
| 配置 | 类型化表单和当前用户值 |
| 授权 | 请求、实际授予、系统条件、撤销与期限 |
| 运行记录 | 触发来源、任务、动作、回执、验证和失败原因 |
| 开发调试 | 文件或规则、校验、模拟事件、只观察、试运行和版本 |

### AI 编程闭环

1. AI 查询实际设备能力和 Schema，不凭空使用候选 API。
2. 生成包与说明，运行清单、入口、依赖和规则校验。
3. 用隔离的虚假数据和模拟事件验证逻辑，只观察模式检查真实目标匹配。
4. 用户审阅具体程序、范围和预期行为后，按已有授权安装或启用。
5. 真机执行并保存必要回执和验证结果。
6. 用户要求修改时，AI 读取授权范围内的诊断并更新程序，不在失败后自动扩大权限或静默发布新版本。

能力目录、JSON Schema、SDK 类型、示例和开发说明来自同一套已实现定义。程序包管理可以供 AI 调用，但管理权限与普通程序调用权限分开。

### 隐私与诊断

默认记录身份、来源、状态、错误、必要匹配元数据和耗时，不长期收集整页文字、短信正文、联系人、输入内容或持续截图。用户可显式开启有期限的专项诊断，界面说明采集内容和删除方式。

模拟事件标注来源，不能伪装成真实系统回执。模拟成功不改变程序的真机验收状态。

## 实施顺序与验收

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| 能力契约 | 能力描述、调用上下文、可用性和错误；提取必要共用端口 | 现有聊天设备路径无行为回退，新目录不暴露未实现处理器 |
| 程序基础 | 包校验、安装、配置、授权、启停、状态库、程序中心 | 无代码程序也能完整安装启停，撤权和卸载清理准确 |
| 事件与规则 | 无障碍来源、持久订阅、过滤、状态机和动作协调 | 真机完成跳广告并通过误匹配与停止场景 |
| 脚本任务 | HTTP、SDK、Node 短任务、资源、定时与恢复 | 请求去重、退出、取消、超时、重连和崩溃结果准确 |
| 能力扩展 | 按用户需求增加通知、识别、外设和快捷入口 | 每一项独立权限、API 与真机验收，不按目录一次性申请权限 |
| 程序生态 | 分享、来源、版本和第三方适配 | 清楚标记受信任代码；需要不可信隔离时另行设计 |

第一版闭环优先完成程序基础、屏幕事件和规则执行，不要求先实现全部候选能力或 Node SDK。契约先统一，但不为未来目录创建空实现。

### 自动验证

- 清单与范围：未知字段和能力、路径逃逸、非法入口、越权订阅、更新扩权、授权撤销竞态。
- 协议：错误版本、重复 requestId、参数冲突、资源归属、临时身份失效、管理 API 越权。
- 事件：过滤、合并、过期、来源世代、持久消费、重复交付、状态缺口、自触发循环。
- 执行：目标不唯一、旧观察、排队期间撤权、取消与完成竞态、超时后实际回执、未知副作用不重试。
- 恢复：任务派发前后崩溃、调度重建、旧版本事件失效、卸载时的任务和会话清理。
- UI：启用与可用性分离、等待点仅消费一次、错误可诊断、停止入口不自动执行其他动作。

可复现缺陷先写失败回归测试，再修复。相关 Node、Python 与 Gradle 检查沿用 [AGENTS.md](../../AGENTS.md)；实现阶段增加与自动化模块有关的测试任务。仅方案文档变更做链接、示例、结构与 diff 检查，不重复完整 Android 构建。

### 真实环境验收

使用已连接手机与已有环境，不自行下载新系统镜像。真实应用无障碍、通知敏感内容、相机麦克风、系统调度、外设以及实际模型或网关分别验收；模拟执行器、模拟网关和单元测试均不能替代。

## 需要在实现中测定的参数

架构与授权边界按本方案执行，以下参数通过首个闭环实测后写入能力定义和配置，而不是使用未经验证的统一默认值：

- UI 观察有效期、候选窗口时长、事件合并间隔、冷却与动作次数。
- 节点遍历深度、队列容量、并发 Node 数量与任务期限。
- 日志、去重、持久附件、缓存和程序业务数据的保留与配额。
- 不同系统版本和厂商环境下可恢复的来源、后台运行与停止行为。
- 需要新增前台服务的具体用途、类型、权限和用户可见状态。

后续实施记录应标明实际实现和逐项验收范围，并同步修订能力状态，不把本设计目录直接当作可用功能列表。
