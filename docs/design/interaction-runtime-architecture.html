1. 现状与决策

已检查根 Gradle 配置、应用 Kotlin 源码、Manifest、现有单元测试与 runtime 脚本目录。设计基线（本轮实施前）的工程只包含 :app、:termux-core、:bootstrap-arm64 三个 Gradle 模块。HTML 中的对话交互尚未落地为 Android 页面。

已验证现状目标边界
MainActivity.kt 同时容纳控制台 Compose 与网关设置；设置直接创建 GatewayStoreActivity 只装配入口；展示层通过用例提交设置，不直接读存储
TestConsoleViewModel 直接 bindService，并持有 RuntimeService 实例ViewModel 只依赖交互领域用例；Service 绑定由 Runtime 客户端实现处理
RuntimeService 同时管理执行、文本输出、通知，并引用 MainActivity执行状态机归 engine；通知与 Service 归 Android 宿主；通知目标由 app 注入
AgentAdapter 将 CLI 输出转为 text/error；RuntimeState 是控制台显示模型公开协议提供结构化执行事实；交互层自行生成 UiState 与中文文案
RuntimeEnvironment 同时安装环境、读取网关、启动 CLI；runtime/ 是脚本目录环境、网关、进程适配留在 runtime-android；脚本目录保留，不冒充 Gradle 模块
确定采用：交互三层 + Runtime 独立子系统 + 纯 Kotlin 契约模块。首期仍在同一应用进程中，通过本地客户端访问执行 Service；独立 Gradle 模块不等于独立进程，不引入不必要的 AIDL/Socket。

模块迁移不同时升级 Compose、Kotlin、AGP。沿用工程现有版本与 JDK 17；新增 Kotlin/JVM 插件与现有 Kotlin 版本对齐。应用安装身份为 com.github.ytlog.mobby.android。Keystore 别名为 mobby.gateway。更换安装身份后，此前已安装的应用数据不会自动迁移。

2. 交互采用三层架构

L1 · 展示层 — :interaction-uiCompose Screen / Component → ViewModel → UiState / UiAction / UiEffect
处理页面、抽屉、展开、输入、焦点、滚动与返回，不执行 CLI。
L2 · 业务层 — :interaction-domainUseCase + 领域模型 + Repository / ExecutionPort 接口
处理发送、切换、配置、Skill 创建等业务规则；纯 Kotlin，可独立测试。
L3 · 数据与适配层 — :interaction-dataRepository 实现 + Room + RuntimeExecutionAdapter
保存会话与草稿，把领域命令转换为 Runtime 请求，把事件投影成会话数据。

“三层”指职责，不是把所有代码强行放进三个模块。运行调用从展示经业务到数据；编译依赖采用依赖倒置：UI → Domain ← Data。Domain 声明端口，Data 实现端口；Domain 不依赖 Data、Android、Compose 或 Runtime 实现。

调用方向：Compose → ViewModel → UseCase → ExecutionPort
                                            ↓ 注入的实现
                                    RuntimeExecutionAdapter
                                            ↓ RuntimeClient
编译方向：interaction-ui ──→ interaction-domain ←── interaction-data
                                                     │
                                                     ▼
                                                 runtime-api
                                                     ▲
                                       runtime-engine / runtime-android

业务层使用自己的 AgentId、ConversationId、TurnId 和错误类型；Runtime DTO 只在数据适配层转换。Runtime 不知道抽屉、会话分组、气泡、折叠、点赞、页面生命周期。

3. Gradle 模块与依赖约束

整个交互入口对 app 暴露为一个独立 Android Library：:interaction-ui。其业务和数据继续拆为两个模块，形成可编译约束的三层。Runtime 对宿主暴露独立 Android Library：:runtime-android，另拆 API 和 engine，避免接口与 Android 执行细节互相污染。

4. Compose 交互实现

采用单向数据流：UiAction → ViewModel → UseCase → Repository Flow → UiState → Compose。页面使用生命周期感知订阅；离开页面只取消 UI 观察，不取消执行。公开入口 InteractionEntry(dependencies, hostActions) 隐藏内部导航与组件。

组件 / 状态所有者实现边界
ConversationRoute / ConversationViewModel组合消息、草稿、执行状态和下一轮配置；按会话恢复，不直接 bindService
PushNavigationDrawer / DrawerState菜单与主内容共用位移进度；内容保持宽度，状态栏与系统导航 inset 独立；背景锁定，返回恢复焦点
MessageTimeline / LazyColumn按 messageId、stepId 使用稳定 key；用户阅读历史时停止自动跟随；按锚点恢复滚动
ExecutionCard / StepContent开始自动展开，完成后按用户手动覆盖状态折叠；普通步骤原地展开，正文高度上限 240dp，短内容自然高度
ReadingSheet / ModalBottomSheet来源、网页、长代码近满屏；最大高度为可用高度减 48dp，短内容自然高度；内部滚动与下拉关闭协调

会话、草稿、手动展开选择与阅读锚点可持久化；当前弹窗、抽屉进度与焦点由 UI/SavedStateHandle 管理；进程句柄、CLI session 与运行真相不进入 ViewModel。UiEffect 只用于焦点、系统分享、文件选择等一次性操作，执行完成与审批必须是可重放状态，不能只用一次性 Channel。

系统选择文件、相机、录音授权由 UI 发起，URI 交给数据层导入为受控资源引用。Runtime 不接收 Compose、Activity、NavController、Uri 或显示文案。Runtime 无法支持的语音、能力、审批操作在 UI 标注不可用，不能用成功提示代替执行。

5. Runtime 是独立执行子系统

边界层 · runtime-apiRuntimeClient / RuntimeCapabilities / CommandResult / RunSnapshot / EventEnvelope
执行核心 · runtime-engineRunCoordinator → RunStateMachine → AgentProtocolAdapter；依赖 ProcessPort、EnvironmentPort、JournalPort、CredentialPort
平台层 · runtime-androidRuntimeService + LocalRuntimeClient + libtermux 进程执行 + 环境安装 + 网关 + 加密配置 + 日志持久化

engine 声明平台端口，runtime-android 注入实现。CLI 协议解析可在 JVM 测试；Android Binder、通知、权限、Keystore、文件路径只留在平台层。对外不暴露 Service、Binder、Process、File、libtermux 类型；外部只拿 RuntimeClient。

首期一个 RuntimeHost、一个 Service 作用域、一个全局执行槽；多个会话可以观察，只有一个任务可被接纳，其他提交返回 Busy(activeRunId)，不隐式排队。锁的权威在 Runtime，不在按钮 enabled 状态。读取状态与查询能力不占执行槽。

Shell 执行保留在 ProcessPort 与内部诊断适配器；产品 AgentId 只含 CODEX / CLAUDE_CODE，诊断能力不通过正常对话的 Agent 列表暴露。网关按 2026-09-21 用户更新统一走本地 Node 桥接；Codex 使用 Responses，Claude Code 使用 Messages，暂不提供协议转换。同协议内容与流式响应保留，已有不匹配配置保留并提示修改。按用户最新授权，Codex 以 Android 应用 UID/SELinux 作为执行边界，使用应用已有权限（danger-full-access、approval_policy=never），不要求手机额外提供 Linux namespace 沙箱；不会取得 root 或扩大系统授权。Claude Code 保留现有原生审批。

Runtime Service 是运行宿主而非永久保活承诺。用户从可见页面启动任务，平台层处理前台服务启动失败、通知和系统超时。现有 Manifest 使用 dataSync；正式发布前需核对执行用途与服务类型是否匹配，不能仅为长时间执行随意选择类型。Android 15 的相关后台时限见 官方超时说明。系统要求停止时，持久化终止原因并清理进程；不能仅停止通知后让进程继续运行。

6. 固定接口契约 · Runtime API v1

以下为接口评审草案；DTO 均位于 runtime-api，具体字段以本节表格为准，代码省略其构造定义。协程接口是进程内调用约定，未来跨进程需要另外实现传输适配器，不能直接把 Flow 当成 IPC。

interface RuntimeClient {
    val connection: StateFlow<ConnectionState>
    suspend fun capabilities(): CapabilityResult
    suspend fun submit(request: RunRequest): SubmitResult
    suspend fun findByRequest(requestId: RequestId): RequestLookup
    suspend fun cancel(request: CancelRequest): CommandResult
    suspend fun resolveApproval(request: ApprovalDecision): CommandResult
    suspend fun snapshot(runId: RunId): SnapshotResult
    fun observe(runId: RunId, after: EventCursor?): Flow<RuntimeUpdate>
    suspend fun readArtifact(request: ArtifactReadRequest): ArtifactReadResult
}

// observe 的首条消息由 Runtime 原子读取快照与序号，随后重放 / 追踪事件。
sealed interface RuntimeUpdate {
    data class Baseline(val snapshot: RunSnapshot,
                        val cursor: EventCursor) : RuntimeUpdate
    data class Event(val envelope: EventEnvelope) : RuntimeUpdate
    data class ResyncRequired(val reason: ResyncReason) : RuntimeUpdate
}

// 领域层端口不暴露上述 Runtime DTO。
interface ExecutionPort {
    suspend fun submit(turn: TurnExecution): Submission
    suspend fun cancel(executionId: ExecutionId): StopResult
    fun observe(executionId: ExecutionId): Flow<ExecutionFact>
}
对象必要字段与语义
RunRequestapiMajor、requestId、agentId、workspaceRef、inputParts、sessionRef?、modelId、reasoningLevel?、gatewayProfileRef、capabilityRefs。输入仅含文本与受控资源引用；不传 UI 状态、原始命令行、密钥或用户可任意拼接的启动参数
SubmitResultAccepted(runId, acceptedConfig) / Rejected(code, retryable, activeRunId?)。Accepted 表示请求已持久接纳，不表示 CLI 已启动或任务已成功
RequestLookupFound(runId) / NotFound / Unavailable。请求应答丢失时先查询原 requestId，不能创建新 ID 自动重发
CancelRequestcommandId、runId、原因 USER_REQUEST。返回 Accepted、AlreadyTerminal、Rejected；Accepted 只表示开始取消
ApprovalDecisioncommandId、runId、approvalId、ALLOW_ONCE / DENY、expectedRevision；过期或不匹配返回 StaleApproval，不能作用到新的审批
RuntimeCapabilitiesapiMajor/minor、engineVersion、availableAgents、每个 Agent 的模型与思考等级、resume/approval/skill 支持、输入限制。不可用含原因；能力不是安装即等于可运行
RunSnapshotrunId、phase、revision、lastSequence、acceptedConfig、sessionRef、pendingApprovals、terminalEvidence?、产物引用、恢复所需输出分段索引
EventEnvelopeapiMajor/minor、eventId、runId、sequence、occurredAt、kind、payload。sequence 在同一 run 中单调递增；排序不使用时间戳
ArtifactReadRequestartifactRef、offset、limit；返回有界内容块及 nextOffset / truncated。只读当前授权工作区的产物，不允许绕过路径校验

补充管理接口

RuntimeAdminClient 同属 runtime-api，提供 listWorkspaces、createWorkspace、initialize、observeEnvironment、listGatewayProfiles、saveGatewayProfile、validateGateway、importResource、listCapabilities、importSkill、saveManualSkill。交互仍经 Domain 管理端口和 Data 适配调用。配置保存与连通性测试返回不同结果；插件只列出与选择，不提供安装接口。Runtime 的目录管理返回不透明引用与名称；界面只展示项目，一个项目绑定一个独立 Git 执行目录，未选项目使用 default 原目录。执行端按项目的目录引用解析实际 cwd，附件按目录绑定；目录并非 Codex 全权限之外的额外沙箱。

凭据写入是单独的短生命周期请求：可携带仅内存存在的 SecretInput，由 runtime-android 立即加密保存；常规读取只返回脱敏摘要与 profileRef，RunRequest、事件、日志及 Room 均不携带密钥。取消导入、无权限、格式错误等返回结构化失败，不产生“已添加”记录。

兼容与失败

主版本不兼容则拒绝执行并提示升级；次版本允许新增可选字段，未知普通事件保留脱敏诊断，未知终态不能推断成功。集中错误码包括 NotReady、Busy、UnsupportedCapability、InvalidConfig、PermissionDenied、ProtocolError、Disconnected、ResourceMissing、StorageFull、Timeout、Interrupted。UI 负责中文映射；接口同时携带 retryable 与 diagnosticRef，不透传未经脱敏的异常堆栈。

命令结果用显式类型表达业务失败；调用方协程取消只取消等待或订阅，不隐式取消已接纳任务。取消执行必须调用 cancel。Runtime 在 Service 作用域接管任务，因此 ViewModel 清理或 Flow 停止订阅不会结束执行。

7. 执行状态、事件与断线恢复

Accepted → Starting → Running ↔ AwaitingApproval
                       │
                       ├─ 成功证据完整 → Succeeded
                       ├─ 执行错误 → Failed
                       └─ 取消 / 超时 → Cancelling → Cancelled / TimedOut

进程或宿主失联 → 重新核实 → 恢复观察 / Interrupted / OutcomeUnknown
ConnectionState 只表达连接情况，不覆盖 RunPhase。

所有非终态均可因启动失败、系统中断或协议错误结束。一个 run 只写入一次终态，由串行状态机决定竞态：若完成已落盘，后续取消返回 AlreadyTerminal；若取消请求先被接纳，则不能再因一个迟到的成功片段宣布成功。成功要求 Agent 协议成功终态及进程退出证据一致；普通 stderr 不直接等于失败。未获得进程退出证据时显示停止中或 OutcomeUnknown，不显示已停止。

事件负载与展示投影
RunAccepted / RunStarted冻结配置、时间和 sessionRef；展示开始状态
Progress固定通知。目前只有 OUTPUT_TRUNCATED，表示输出超过保留上限。界面选择中文文案；思考原文仍在 thinking 步骤里
ToolStarted / ToolOutput / ToolFinishedstepId、固定的 StepBody、输出分段、明确工具终态。StepBody 只有 thinking、command、file_read、file_write、file_diff、action。command 带 command；file_read / file_write 带 path；file_diff 带 paths；action 带 name 与纯文本 detail。输出分段依次是思考原文、命令结果、文件内容、unified diff 或动作结果。回复是 AssistantDelta / AssistantCompleted，不是步骤。上层按这些类型读取，不再从工具 JSON 猜测字段
AssistantDelta / AssistantCompletedmessageId、chunkIndex、文本增量 / 完成标记；消息完成不是 run 成功的替代信号
ApprovalRequired / ApprovalResolvedapprovalId、revision、ApprovalSubject。Subject 与步骤同形：command、file_read（path，以及 offset、limit）、file_write（path 与 content）、file_diff（paths 与 diff）、action（name 与 detail）。类型之外的输入键不会成为审批。决定仍按 CLI 的 request id 允许或拒绝一次。待审批进入快照，重连后仍可见
CancellationRequestedreason。目前只有 USER_REQUEST。快照阶段变为 CANCELLING，并清空待审批
ArtifactAvailable / RunFinished受控产物引用 / 终态阶段与 TerminalEvidence（protocolSucceeded、exitCode、error、terminationConfirmed）。RunFinished 只接受终态阶段。UI 自行决定折叠和操作

避免漏事件与重复执行

  1. Domain 生成 requestId，Data 在交互数据库先保存待提交轮次与请求记录，再调用 Runtime。Runtime 对 requestId 与请求摘要做幂等检查；相同 ID 相同参数返回同一 run，不同参数返回冲突。
  2. Runtime 持久接纳记录后才回复 Accepted；日志和执行槽接纳必须原子化。数据层应答丢失时查询同一 requestId。进程在接纳后启动前崩溃，恢复时标为中断待用户决定，不自动重新执行有副作用的命令。
  3. 首次订阅获得 Baseline(snapshot, cursor)，再连续读 cursor 之后的日志。持久日志为权威，实时通知仅作唤醒信号。恢复订阅在 after 游标有效时重放后续事件，不重新应用基线内的文本。
  4. Data 在同一数据库事务中应用事件并推进游标；按 (runId, sequence) 去重，缺口先补齐。日志已压缩时返回 ResyncRequired，再从一致快照与输出分段索引重建投影，不把增量再追加到已有全文。
  5. UI 退后台可暂停绘制；事件接收与投影由应用/Service 生命周期的同步器处理，或稍后可靠重放。慢消费者不阻塞进程 stdout 读取：输出写有界分段文件，事件引用分段；容量到达上限明确标记截断，状态与审批事件不能静默丢弃。

日志清理仅针对终态 run，保留期与大小预算可配置；清理后保留幂等请求摘要和终态索引。活跃任务的终态、审批与最新一致快照不随普通输出裁剪。写盘失败时拒绝新任务；执行中则请求安全停止并报告 StorageFull，不能把未持久化接纳当作可靠成功。

8. 关键交互调用链

发送与停止

点击发送 → SubmitTurnUseCase → 保存待提交轮次 + draftRevision
        → RuntimeExecutionAdapter → RuntimeClient.submit
        → Runtime 接纳 / Busy / 配置错误
        → Accepted 后只清除原 draftRevision（期间新输入保留）
        → Runtime 事件 → 数据投影 → Flow → Compose

点击停止 → StopRunUseCase → cancel(runId)
        → Cancelling → 终止进程组 / 等待退出证据
        → Cancelled / TimedOut / OutcomeUnknown → UI 更新

与moddy对话创建技能

CreateSkillConversationUseCase 创建新的普通会话，保留原会话草稿与运行；绑定 Skill Creator 能力引用，预填“请用 /skill-creator 帮我创建技能，要求是：”，光标置末。用户补充并发送后，适配器按真实 CLI 支持方式调用 Creator，不能假设两个 CLI 都直接识别同一斜杠命令。生成结果通过 ArtifactAvailable 在会话展示；预览、校验和明确保存后写入受控技能目录。若 Creator 不可用，返回 UnsupportedCapability，不悄悄转成手动表单。

“手动创建”走独立表单与 saveManualSkill；“导入技能文件”走系统文件选择、Markdown 校验和同名处理。这三个入口共享技能存储与校验，只有对话创建需要新的 Agent 运行。

模型选择、切换会话与抽屉

模型与思考等级保存为 NextTurnConfig，submit 时冻结为 RunConfigSnapshot。运行中修改不影响当前任务；更换 Agent 导致新的会话，不跨 CLI 复用 session。切换会话仅改变 Repository 的观察目标，不调用 cancel。抽屉、原地展开、近满屏面板均停留在 UI，不向 Runtime 发送“打开/关闭”命令。

审批与应用恢复

只有 Runtime 报告支持且实际产生审批事件时显示授权操作。用户决定经用例传回 approvalId 与 revision；页面消失不默认批准。应用重新打开，先查询连接与 run 快照，再恢复会话投影；连接断开显示“连接中断，结果待确认”，不得将 busy=false 当作已完成。

9. 存储所有权与安全边界

所有者保存的数据边界
interaction-data / Room项目与执行目录关联、会话迁移、消息投影、轮次请求映射、草稿、附件引用、展开选择、阅读锚点、消费游标展示与业务数据；不直接读取 Runtime 数据库
runtime-android / RuntimeJournalrequestId 幂等记录、run 状态、sessionRef、冻结配置引用、事件序号、审批、输出分段与产物索引执行权威；不保存对话标题和抽屉选择；Engine 通过 JournalPort 访问
runtime-android / GatewayStore网关配置、凭据加密值保留原 SharedPreferences 名称与 Keystore 别名；仅管理接口接收临时明文
runtime-android / ResourceStore导入附件、技能文件、工作区引用和 CLI HOME验证路径与授权；会话迁移不移动或删除目录和历史文件
interaction-ui / SavedStateHandle当前页面、选中会话、临时面板状态不包含密钥、运行句柄或大段日志；抽屉动画进度无需长期持久化

两个数据库各有单一写入所有者，跨库通过幂等请求和可重放事件实现最终一致，不声称有跨库原子事务。运行配置只保存 profileRef 与配置版本引用，密钥轮换不把明文复制进 RunSnapshot。附件传入前由 Android 适配处理 URI 授权和导入；Runtime 再验证 workspaceRef 与 artifactRef 范围，拒绝路径穿越和任意文件读取。

Room 已接入会话与项目存储。交互库只定义当前结构：Room 使用 Android 允许的最低版本 1，不导出历史 schema，也不提供旧版本迁移或自动升级；当前文件为 interaction-current.db，不读取旧 interaction.db。以后开发阶段修改结构时，先清除当前交互开发库再创建新结构；SharedPreferences、HOME、workspace 和 CLI 配置存于别处。真实配置、输出中的凭据及本地路径敏感信息不得放进源码、测试夹具或文档。
