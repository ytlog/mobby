# AI 服务的简化连接流程

2026-11-01 在手机上实际配置网关时，需要依次处理服务菜单、站点、Base 地址、Key、「获取模型」、多选保留模型、「设为默认」和「保存网关」，普通用户难以理解。本设计把新建和编辑统一为“选服务 → 粘贴 Key → 保存”三步，替代 [网关 Provider 配置引导](gateway-provider-onboarding.md) 中「页面与行为」的旧表单交互。协议、探测、加密存储和授权边界不变。

## 名称

界面统一把“网关”称为“AI 服务”（English: AI service），例如「添加 AI 服务」「AI 服务设置」。代码、存储、Keystore 别名 `mobby.gateway` 和协议文档继续使用 gateway，不迁移数据。

## 页面

1. **选服务**：服务按卡片平铺，按界面语言排序，与原服务菜单一致；最后一项是「其他服务（填写地址）」，即原来的「自定义」。新建时不预选任何服务，Key、地址和保存按钮在选定服务后才出现。编辑已有配置时选中它对应的服务。
2. **填 Key**：
   - 只有一个「API Key」输入框，旁边有「粘贴」按钮，点按后才读取一次剪贴板。
   - 输入框下方是「还没有 Key？去官网领取」，以及该服务原有的费用与额度说明。OpenRouter 仍可登录授权。
   - 选「其他服务」时，Key 上方多一个「服务地址」，规范化规则与原 Base 地址相同。
3. **保存**：点击「保存」，加载期间显示「正在保存…」，依次完成：
   - 获取模型列表（`GET {基址}/models`）。失败时显示原因（Key 无效、地址没有模型列表、域名无法解析、证书或超时），不保存。
   - 确定默认模型，按以下优先级：
     1. 编辑时，使用已保存的默认模型；
     2. 预设服务的推荐模型出现在列表中；
     3. 列表只有一个模型。
     
     都不满足时，打开「配置模型」使用的同一份列表，设好默认后再点「保存」。
   - 服务没有模型列表时，显示「模型 ID」输入框，填写后再次点「保存」。
   - 用默认模型探测原生协议并加密保存。成功后返回列表，并提示「已连接，可用于 Pi、Codex…」；失败时保留表单并显示原因，不写入可执行路由。

保存按钮下方说明：保存前会发送一条小请求验证连接，可能消耗少量额度。

## 模型

- 新建时可以直接「保存」，有默认模型时会保留服务返回的完整列表；编辑时保留已有选择。每个服务最多保存 2000 个模型。
- 点「配置模型」打开可搜索的列表，勾选要保留的模型，再点对应行的「设为默认」。设为默认会同时勾选该模型。已有配置会显示之前的勾选状态，列表底部也可填写其他模型 ID 作为默认。最后点「保存」，探测通过后保存。
- AI 服务列表展开时，模型多于 8 个就显示搜索框，最多列出 30 个匹配项；当前选中的模型始终显示。

推荐模型仅用于预设服务，且只有出现在服务返回的列表里才会选用；否则请用户自己选。当前推荐：

- DeepSeek：`deepseek-chat`
- OpenAI：`gpt-5`
- Anthropic：列表中第一个 `claude-sonnet-` 开头的模型

推荐不会自动选中免费路由（例如 `openrouter/free`），也不会按价格过滤。

## 高级设置

默认收起。点开后箭头翻转，页面滚动到展开的选项。包含：

- 国内站/国际站切换（仅限有两个站点的服务）；
- 官方使用说明；
- 检查已保存的连接（仅编辑时）；
- 删除（仅编辑时）。

## 不变的约束

- 切换服务、站点或地址时，清空待提交的 Key，并以空凭据覆盖。重选同一服务时保留 Key。未连接成功时不改动设备上的配置。
- 剪贴板只在用户点「粘贴」时读取，内容只填进 Key 输入框，不写入日志或 SavedState。
- 探测失败、取消和超时如实显示，不能显示为成功。
- Pi、Codex、OpenCode 只用 Responses，Claude Code 只用 Messages。

## 验收

单元测试覆盖以下行为：

- 新建时先选服务；
- 一次点按完成模型获取与保存；
- 推荐模型只在列表中出现时才选用；
- 只保存勾选的模型，使用单独设置的默认模型探测；
- 没有模型列表时可填写 ID；
- 获取失败不保存；
- 「粘贴」读取剪贴板；
- 高级设置中的站点切换与删除；
- 切换服务清空 Key；
- 列表中模型多于 8 个时可以搜索。

2026-11-01 在 Xiaomi M2007J1SC 上验收（versionCode 92）：

- 用户用新页面选「其他服务」、填地址、粘贴自己的 Key 并连接成功，设备上生成加密的路由配置。
- 随后 Pi 正常回复，应用内 `npm ping` 成功。
