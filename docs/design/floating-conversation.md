# 悬浮对话

## 职责与复用

悬浮球不是独立进程或 Gradle 模块：窗口管理在 `DesktopPet` / `SystemPetWindow`，拖动、位置与显示规则在 `PetLogic`，托盘在 `PetTrayView`，Application 负责连接会话状态。新增的 `FloatingConversationWindow` 仅负责系统窗口、Compose 生命周期、键盘焦点和屏幕操作时的临时隐藏。

悬浮对话使用原有 `ConversationViewModel`、`InteractionUseCases` 和 `Timeline`。草稿、排队发送、流式消息、工具与设备卡片、错误、停止任务以及历史记录沿用 App 的执行与存储路径，不另建聊天数据库、网关或 Agent。`QuickConversation` 仅适配快捷建会话与选择屏幕插件；`FloatingConversationContent` 提供紧凑窗口和文字输入。

## 使用

在设置开启悬浮球，并授予系统悬浮窗权限。离开 App 后点击悬浮球，再点击「悬浮对话」。有当前任务时进入同一个会话；空闲时首次创建会话，后续恢复上次悬浮会话。可用默认网关/模型的选择沿用既有解析规则。

在窗口直接输入并发送，或点击「识别屏幕」。识别入口先通过原有插件目录和权限验证启用 `plugin:device:screen`，有草稿时发送用户的问题，空草稿时发送仅观察屏幕的提示。设备权限不足时显示实际原因，保留草稿，不伪造结果。屏幕读取仍由现有 Agent 与插件执行，不保证 Agent 一定会调用屏幕工具。

空会话中的「使用手机」「查看照片」「访问文件」「使用相机」卡片直接在悬浮窗选择对应插件，选中后显示勾选状态，不发送任务、不跳转 App。权限不足时在悬浮窗显示原因；完整插件管理与系统权限授予仍需进入 App 或系统设置。卡片选择与「识别屏幕」共用现有插件目录及 `setPlugin` 权限校验。

窗口展示现有消息时间线，支持停止、收起、新建和「回到对话」。回到对话打开 App 中同一会话；需要完整附件、插件设置、长文阅读、分享等操作时进入 App。识别屏幕和新建操作不覆盖已有会话草稿。窗口收起不会取消任务，草稿继续由原有队列保存。

悬浮球和对话窗口在屏幕工具操作期间同步脱离 WindowManager，所有操作释放后恢复；嵌套隐藏不会提前恢复。进入 App、禁用悬浮球或撤销权限时关闭对话窗。生命周期跟随宿主应用进程，未新增常驻服务。

## 屏幕读取后停止刷新与发送草稿修正

系统悬浮窗读取底层屏幕时会 detach。AndroidX 的窗口 Recomposer 随 detach 取消；此前使用仅在 Lifecycle 销毁时释放 Composition 的策略，导致重新 attach 后沿用已停止的 Composition，后台与数据库已经完成、悬浮窗仍显示执行中，输入框也可能停留在旧显示。改为窗口 detach 时释放 Composition，attach 时重新创建；ViewModel、会话、任务和草稿仍复用原实例。参考 [Compose 在 View 中的销毁策略](https://developer.android.com/develop/ui/compose/migrate/interoperability-apis/compose-in-views)。

增加使用真实 LifecycleAware WindowRecomposer 的回归测试：先显示会话，执行屏幕操作隐藏/恢复，再发布更新，确认新内容能够显示。原测试环境共享 Recomposer，不会自动复现真实窗口 detach 后的取消，因此只检查窗口重新挂载不足以验证刷新正常。

另修正草稿内容版本：仅光标或选择范围变化不递增发送内容版本，避免成功发送后误认为还有新内容而保留原消息。新输入文字、附件与插件变化仍按已有版本规则保护草稿；拒绝或结果未确认仍保留输入。数据层回归覆盖发送准备后移动光标、收到接受确认、原消息仍在历史而输入草稿清空。

2026-09-28 本次修复验证：两项新增回归均先在原实现失败、修复后通过。interaction-data 全部 61 项与 interaction-ui 相关 33 项测试通过；JDK 17 下 App Debug 构建、Termux 单元测试与 App lint 通过（App JVM 测试当前无测试源）。已覆盖安装到连接的小米手机，在桌面悬浮窗通过真实网关执行屏幕识别，确认输入框在接受发送后清空，屏幕读取隐藏/恢复后继续显示执行步骤、流式回复和完整结果，最终任务状态为 SUCCEEDED 且窗口退出执行中；原会话中后来修改的草稿保持原样。此前记录的无关 UI 全套失败尚未处理。

## 悬浮界面视觉调整

悬浮对话采用 26dp 圆角、轻阴影和细边框，顶部用紧凑标题与 Agent 名称配合新建、打开 App、收起三个图标操作（保留可访问名称和 48dp 点击区域）。有内容时显示单行会话标题与执行状态；空会话使用适合小窗口的欢迎区，仍复用原插件卡片及选择入口。输入区改为一体化圆角卡片，屏幕识别和发送按钮归入同一操作栏，深浅色跟随原外观设置，使用品牌蓝的低透明度底色。对话消息、设备操作、附件和任务执行继续复用 Timeline / ViewModel / use cases。

悬浮球菜单同步使用对话图标和实色主按钮突出悬浮对话入口。真机检查另外复现键盘遮挡输入区：现代 Android 的固定尺寸悬浮窗仅设置 adjustResize 不足以避开 IME，改为让 WindowManager 在布局时明确避开 IME 与系统栏，并将可输入窗口的根视图高度改为 WRAP_CONTENT，由 Compose heightIn 设置高度上限，使键盘出现后的重新测量遵循真实可用高度；普通悬浮球不启用 IME 避让。参考 [WindowManager 窗口避让类型](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#setFitInsetsTypes(int))，此路径用于 API 30 以上，低版本保留原 adjustResize。

2026-09-28 验证：相关 UI 回归 36 项全部通过，Debug 构建、App lint 通过，App/Termux 单元测试检查通过（App 无 JVM 测试源）。键盘布局协议回归先在旧实现失败，再修正窗口避让及根视图测量。已覆盖安装到小米 Android 13 手机，检查悬浮菜单、空会话、键盘展开后的输入区与发送按钮、输入文字启用发送、删除测试文字及收起键盘；没有提交测试消息。低于 API 30、深色真机和横屏尚未做设备验收。

## 发送后收起输入区

在消息已被接受（存在执行 ID 或已入队）且本地与持久草稿均为空、没有待处理附件时，输入卡片自动收成右下角悬浮工具条，同时收起键盘，留出更多对话空间。工具栏保留继续提问、屏幕识别和运行中的停止入口；继续提问展开原输入框并请求焦点，空输入可手动收起。下一条消息被接受后重新收起。新会话、发送失败或仍有新文字/附件的草稿保持展开；仅改变展示状态，不清空草稿或新增发送路径。内容区不再为收起的输入卡片保留整行空间，尾部保留安全留白；回到最新内容按钮放在工具条上方。布局选择按会话保存，继续复用既有 ComposerState、Timeline 和 ViewModel。

UI 回归覆盖接受消息后折叠、重新展开、再次接受后折叠，以及拒绝发送/保留下一条草稿时保持展开。JDK 17 下相关 UI 测试 38 项、Debug 构建、App lint 通过。

窗口高度上限从 560dp 增至 680dp，小屏幕和键盘出现时仍按可用范围约束。屏幕工具隐藏/恢复会重建 Composition：持久阅读锚点不能代表用户主动暂停跟随，因此悬浮会话通过原 ViewModel 保留每个会话的跟随意图，Timeline 仍使用原滚动收集器。回归测试先复现保存锚点后恢复窗口不跟随新回复，再验证恢复后能看到末尾回复；原渐进跟随/暂停阅读位置测试继续保留。
