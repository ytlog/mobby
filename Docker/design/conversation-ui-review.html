1. 整体设计方向

主界面就是对话，左侧抽屉管理会话，底部输入区承接文本、上下文与语音。这版依据用户提供的六张截图，替换 v2 的“列表首页”路径。抽屉是模态导航，不是缩小的桌面常驻侧栏；打开时保留主界面位置，关闭后继续阅读。

阅读优先回复直接排版，过程紧凑成组；正文不被固定工具栏遮住。
操作就近代码工具在代码顶部，消息操作在回复底部；输入操作在拇指区域。
状态可信运行、待确认、失败、中断分别呈现；原型能力和真实运行能力明确区分。

执行开始自动展开当前过程，确认成功后收起未被用户手动操作的过程。最终答复、失败摘要和待确认事项保留可见。本文是完整 UI 交互设计与浏览器原型，不是 Android 运行代码实现。

Android 交互依据

  • Android 布局和导航：选择用户熟悉的页面导航与主操作；本文采用对话主屏、模态抽屉与详情路径，新建入口在顶部和抽屉内。
  • Compose Predictive Back：系统返回预览实际目的地，取消手势不能提前更改页面或草稿。
  • Compose Window Insets：按状态栏、导航栏、显示切口和 IME 的实际 inset 布局。
  • Compose 无障碍默认行为：保证交互目标至少 48 × 48dp，并提供清楚的语义描述。

Android 规范支持的是平台行为；对话主屏、抽屉管理会话等仍是本项目的产品设计决策。本文不承诺当前依赖版本已覆盖全部预测返回动画，实施时需检查并做设备验证。

3. 代码现状与设计前提

以下是静态代码检查事实，未据此声称手机运行验收通过：

  • MainActivity.kt 的 TestConsoleScreen 当前展示运行状态、Agent 切换、文本输出列表和输入框。
  • TestConsoleViewModel.kt 绑定 RuntimeService，只有一个输入草稿和一个运行状态。
  • RuntimeService.kt 只允许一个忙碌任务，输出存于内存；最多保留 2,000 行、约 1,000,000 字符，单项会截断。不能直接用它作完整会话数据库。
  • AgentAdapter.kt 将 Claude stream-json / Codex exec --json 事件转为 AgentOutput(text, error)，UI 已失去工具调用 ID、轮次和事件阶段。
  • 当前命令参数没有恢复既有 CLI 会话的路径。增加历史列表并不自动获得多轮上下文连续性。
  • 已有 Compose、协程、libtermux、前台服务和加密网关存储应继续使用。

因此需先改事件模型、会话持久化与 CLI 会话绑定，再构建交互。不能从日志里匹配“完成”几个字来折叠，不能把 stdout 每一行当作一条完整回复。

4. 完整页面与 Android 导航

4.1 页面地图

对话主屏（最近对话 / 新对话空态）
├─ 左上菜单 → 会话抽屉
│  ├─ 新对话、置顶、项目、历史会话
│  ├─ 底部搜索 → 按标题过滤
│  └─ 设置 → 网关 / 运行环境 / 外观 / 归档
├─ Agent 胶囊 → 当前 Agent / 模型 → 新建不同 Agent 的对话
├─ 顶部新建 → Agent + 项目配置面板 → 空对话
├─ 更多 → 重命名 / 置顶 / 归档 / 会话信息
├─ 执行卡 → 步骤详情（全屏）
├─ 代码卡 → 全屏代码；来源 → 来源详情
└─ 底部输入 → 上下文面板 / 语音面板 / 发送或停止

首启显示空对话；后续恢复最近访问的对话和阅读位置。抽屉切换对话不堆叠导航历史；Android 返回不会逐个遍历之前切过的对话。详情页与设置页入栈，模态面板只保留一层，同级面板替换而不无限叠加。

4.2 顶部与侧栏

顶部由三个视觉组构成：48dp 圆形菜单按钮；显示实际 Agent 的胶囊；新建与更多组合胶囊。下方一行显示项目、会话标题和真实状态。工具栏占据布局空间，不覆盖正文，不做重度模糊。未读变化只在有真实未读事件时显示圆点。

抽屉宽度建议 min(360dp, 可用宽度 − 32dp)。顶端显示 mobby / 本机与新建；置顶、项目、历史分组；底部固定搜索和设置。中部独立滚动，IME 出现后搜索上移，历史区域收缩。点击遮罩、关闭按钮或系统返回都可收起；不通过自定义左边缘滑动与系统返回抢手势。选中行用浅层背景、标题与状态识别，运行中切换不停止任务。

项目是“目录 + 对话归属”，不等于新容器或云工作区。选择项目后默认新建该项目下的对话；新建项目要先验证目录可访问。移除项目分组不得删除目录。第一版不承诺后台多 Agent 并行。

4.3 对话与详情

单栏正文左右 16dp，用户气泡靠右，Agent 正文不加大气泡。执行卡细边框、圆角 16dp，内部按顺序排列公开进度和工具；默认展示已接收的真实步骤。成功摘要示例“已完成 · 3 个步骤 · 18 秒”，正在执行不显示虚构完成时间。长过程可分页加载；没有工具事件时不补假步骤。

工具步骤点击打开全屏执行详情：名称、状态、参数摘要、工作目录、耗时、退出码、可用输出；较长输出按需读取。代码块提供语言、全屏、复制、换行，默认保留格式并可横向滚动；全屏返回恢复原位置。来源只展示可解析的标题/域名/本地路径，引用标记由专用渲染器处理；无法解析时显示“来源不可用”，不把协议 token 当正文。

4.4 输入区

底部为圆角输入容器，左侧加号，多行输入居中。空闲且无文本时右侧为语音；有文本或上下文时变为发送；执行中固定为停止，不随草稿变化。执行时仍能写下一轮草稿，当前不支持偷偷排队或直接注入。其他对话运行时显示“查看任务”入口，发送禁用；上下文和草稿继续保留。

正文建议 16sp，次要信息 12–14sp，系统字重与行距随无障碍设置。输入 1–5 行，超过后内部滚动；长路径省略中段；所有动作至少 48 × 48dp。顶栏与输入区颜色由主题决定，默认跟随系统，深浅两套均可读。原型默认深色是为了对照参考图，不规定产品强制深色。

5. 时间线结构

一段对话包含多个轮次，每轮按以下顺序组织：用户消息 → Agent 的公开进度说明与工具事件 → 最终答复 → 产物入口。过程按真实时间顺序显示，不将晚到日志插入其他轮次。

内容默认呈现允许折叠
用户消息浅色气泡、保留原文长文本可“展开全文”，不随运行结束折叠
公开进度说明普通段落；过程中按事件顺序显示完成后随过程组收起
计划CLI 确有计划事件才显示步骤与状态可折叠，不能伪造完成百分比
工具调用名称、简述、状态、耗时外层过程初始展开，内部长输出默认只露摘要
最终回复Markdown 正文不自动收起
文件 / 产物紧凑入口，显示真实可用项目数详情单独打开
权限请求待处理卡片 + 操作范围未处理时不可被父级折叠遮住
失败 / 超时 / 停止明确结果与后续动作状态摘要始终可见，日志可折叠
未识别事件“暂不支持展示的事件” + 脱敏详情不丢弃、不算成功步骤

“过程”仅指 CLI 提供的公开说明、工具活动与输出，不展示或推测模型隐藏思维链。非流式网关等待期间显示“等待响应”，收到真实事件后再更新；不伪造逐字输出、步骤或进度。

6. 展开与折叠：明确规则

每轮设 expansionOverride = AUTO | OPEN | CLOSED，每个工具详情另有独立开关。业务状态与展开状态分开保存。

触发AUTO 默认行为已有用户选择时
新轮次开始过程组展开；当前步骤显示摘要新轮次有独立状态
步骤正常完成、整轮仍在运行保留步骤行；长输出收为摘要手动打开的步骤详情保留
整轮确认成功最终回复已写入后，过程组收为一行OPEN 保持展开；CLOSED 保持收起
失败、超时、取消、异常中断过程保留展开；显示常驻结果条可保持过程收起，但异常摘要必须在组外
权限请求或需要回答待处理卡片放组外；列表标“待处理”折叠选择不影响卡片
切换对话 / 屏幕旋转恢复该轮选择与阅读位置不重置
打开历史成功轮次默认折叠持久化 OPEN / CLOSED 优先

完成时的自动折叠须同时满足：没有未完成步骤或待处理请求、结果事件及退出状态一致、用户未手动选择、用户没有在过程内选中文本或停留阅读。用户上滑阅读时推迟本次自动折叠，提供“收起过程”入口；不要一空闲就突然收起。回到底部或重新进入对话后才重新应用 AUTO 默认值。

展开动画建议 160–220ms，遵守减少动画设置。折叠前记住首个可见项 ID 与偏移并恢复，保持视口锚点。焦点位于即将隐藏区域时延迟折叠。展开按钮语义包含“已展开/已折叠、步骤数、状态”。

摘要示例：已完成 · 5 个步骤 · 32 秒、已结束 · 1 个步骤失败、已停止 · 部分操作可能已执行。工具失败后恢复成功时仍保留“含 1 次失败，后续已恢复”标记与入口；不得把错误历史改写为全部成功。

7. 具体交互流程

新建与继续

首次进入显示“今天，做点什么？”和任务输入；缺少依赖时显示初始化入口。点击新对话打开底部配置面板，选择 Shell / Claude Code / Codex 与已授权工作区后进入空对话页。首条发送后固定 Agent 和工作区，切换 Agent 新建对话。模型改动仅影响后续轮次，历史只存配置引用。缺少依赖或网关时显示配置入口并保留草稿。只有服务确认接收并持久化轮次后才清空输入；提交失败保留原文并提示原因。首条消息生成可编辑标题；首版可用本地截取，不额外调用模型。

继续对话使用绑定的 CLI session ID，恢复能力需对内置 CLI 的实际版本验证。恢复失败必须说明“无法恢复会话”，提供重试恢复或新对话，不得悄悄启动无上下文的新任务。Shell 每次启动独立命令，标题旁注明“工作目录保留，进程内变量不跨轮次保留”。

执行、停止与重试

首版全局单任务运行。用户可切换并阅读其他对话、编辑各自草稿；其他对话发送区显示“另一个对话正在执行”及跳转入口，不自动排队，也不通过 UI 暗示已接受任务。运行中继续输入仅保存草稿，首版不做中途消息注入。

停止按钮立即转为“停止中”，重复点击禁用。确认进程组终止后才标“已停止”；终止确认失败显示“停止状态待核实”，不释放运行锁或伪装成功。停止与完成竞态由已记录终态和执行证据判定，不由最后一条 UI 文案决定。

失败提供“编辑后重试”；重试创建新轮次，旧轮次保留。不得自动重发已可能产生副作用的命令。后台通知点按回到实际运行对话；后台期间折叠规则与前台一致。系统通知权限被拒绝时仍在应用列表和对话页显示真实运行状态；不得声称通知已送达。前台服务遵守系统启动与时限约束，切到后台不承诺永不终止。通知锁屏内容默认只显示任务状态，不包含命令、密钥或正文。

权限与中断

仅在适配器能接收真实请求并可靠回传决定时启用“允许本次 / 拒绝”。显示命令、目录、影响范围；默认不提供绕过沙箱或永远允许。当前非交互执行路径能否支持此交互尚未验证：未接通时显示能力限制与错误，不展示无效批准按钮。

进程重建先检查运行服务是否仍持有执行实例；若无法关联活跃实例，则记录“上次执行中断，结果未确认”，保留输出与草稿，不自动重发。切换对话不会停止任务；归档不等于停止。首版禁止归档运行中的对话，并明确说明原因。

滚动和详情

处于底部时跟随新输出；用户上滑、选中文本时暂停跟随，底部显示“有新内容 ↓”。详情返回保持原轮次、草稿和滚动锚点。正文代码块允许独立横向滚动，页面本身不横向溢出。系统返回与工具栏返回按第 4.5 节区分处理，不附带停止副作用。

对话管理

抽屉标题最多两行，工具栏上下文单行省略；长按/更多菜单支持重命名、置顶和归档。归档支持撤销，不删除 HOME 或工作区。搜索首版仅标题；列表按最近用户提交或轮次结束更新排序，流式 token 不触发重排。选中的对话不因排序跳走；未读完成标记在用户打开后清除。永久删除和全文搜索后置。

语音输入完整流程

点击语音 → 说明用途并按需申请麦克风权限 → 就绪 → 开始录音 → 用户结束 → 转写中 → 可编辑文字 → 放入输入框。插入位置为当前光标；选中文本时仅替换所选部分。取消录音不修改原草稿，关闭面板/切到后台立即停止采集，电话或音频焦点中断显示中断状态。永久拒绝权限提供系统设置入口，普通拒绝提供文字输入替代。无识别服务、空音频、超时或离线错误有明确提示，可重录。

语音能力先检查 Android 识别服务与语言可用性；是否经过网络取决于选定的识别实现，不承诺全部本地。音频默认不持久化，转写服务和隐私说明明确后才接入。HTML 只模拟就绪/录音/文字校对，不申请权限或采集声音。

加号面板：从底部展开

点击输入框左侧加号：先保存草稿和选择区，收起 IME，再以约 220ms 的上移动画从屏幕底部展开，背景加遮罩；内容区覆盖输入栏，但不改变对话滚动位置。面板自然高度约半屏至三分之二屏，小屏和大字体下允许内部滚动。圆角建议 28dp，首排卡片约 96–110dp 高；所有行可整行点击。左右不出现桌面弹窗边距，底部处理系统导航 inset。

点击遮罩、系统返回、拖动条点击或从拖动条下滑可关闭；内容滚动与下滑关闭不能抢手势。二级项目页返回本面板，关闭后焦点回到加号，草稿与附件保持。减少动画开启时取消位移动画。原型实现底部展开、拖动条下滑/点击和 Escape 返回；实际 Android 使用 ModalBottomSheet。

插件/技能页需要真实能力发现，空态说明暂无可用项目；联网搜索的自动/开启/关闭是任务偏好，不能覆盖 Agent 权限和沙箱，也不能在不支持的网关上伪装生效。此原型允许体验选项，正式版本必须按能力启用。相机/照片仅展示后续流程说明，本地文件可添加明确标注的示例。

上下文与附件

加号采用新增参考图的底部模态面板：顶部拖动条，首排三个等宽圆角入口“拍照 / 照片 / 本地文件”；下方依次为“插件 / 技能 / 联网搜索”，搜索行右侧显示当前偏好（默认“自动”）。语音仍由输入框的语音入口进入，不混入本面板主列表。图片和拍照只有 CLI、协议和网关全链路验证支持后才开放。用系统选择器获取用户选择的 URI，展示名称、大小、处理状态与移除按钮，不申请宽泛文件访问权限。对任意 Android URI 先导入到 app 私有可用区，不能直接当 CLI 文件路径。

加载失败可重试/移除；处理中发送禁用，取消选择不变更原草稿。格式、字节上限和 token 预算由能力描述给出并在发送前校验；失败说明具体限制，不静默裁切后提交。上下文仅属于当前对话草稿，切换对话不串附件，重启后失效授权需重新选择。工具原始输出及附件全文不进入普通日志。

回复操作与设置

最终回复下提供复制、系统分享和追问；追问建议只写入输入框，需要用户再点发送。分享先显示所选内容范围，默认只有最终回复，不带日志、密钥与工作区完整路径；再调用 Android Sharesheet。重试创建新轮次，不能用“重新生成”隐藏已执行的副作用。点赞、朗读与导出工具只有完整功能存在时再加入。

网关页分别选择 Claude Code / Codex，显示协议、地址、模型、密钥与保存。输入错误就地提示，返回未保存改动时提供保留编辑/放弃；保存成功仅表示设备加密存储完成。若后续提供连接测试，必须单独展示测试范围与结果。运行中的任务使用启动时配置快照，新设置只影响后续轮次。Shell 不使用网关密钥。运行环境页展示真实依赖状态及重试初始化；主题提供跟随系统/浅色/深色。

GatewayStore：继续负责加密配置，UI/Repository 仅持有非敏感引用

导航根为 Conversation(id?)，抽屉切换只替换 id；RunDetail、CodeDetail、Settings 为独立目的地；Drawer、AgentPicker、ContextPicker、Voice、More 用互斥的 OverlayState 管理。SavedStateHandle 只放目的地 ID 与轻量状态；长消息与日志放数据库/文件，避免 Bundle 过大。输入草稿持续持久化，不能只依赖 remember；Lifecycle 恢复后按 runId 重新订阅既有执行，不重发命令。

Android 交互扩展

新增 ProjectRepository 管理 workspace 关联，AttachmentRepository 管理 URI 授权、导入及预算，SpeechInputController 管理录音/转写生命周期。Clipboard 与系统分享通过平台接口执行。语音、面板开关、代码换行不改变运行状态；审批决定必须通过 ExecutionCoordinator 的真实 requestId 回传。

CapabilityDescriptor 按 Agent 与网关暴露 supportsImages、supportsAttachments、supportsApprovalResponse、supportsResume 等已验证能力；控件由能力决定启用，不仅靠 UI 选项。模型显示采用已配置名称，不虚构快速/高级能力。MessageRenderer 分离 Markdown、代码、来源，HTML/链接只允许安全渲染，不执行模型提供的脚本或任意 scheme。

事件包括 RunStarted、Progress、TextDelta、ToolStarted、ToolOutput、ToolFinished、ApprovalRequested、ArtifactProduced、FinalMessage、RunFinished、UnknownEvent。这是内部模型草案，不声称是两套 CLI 的原生字段名。

同一 run 内串行接收并分配单调序号；以真实 event ID 去重，缺少 ID 时通过适配器区分快照与增量，不能仅凭相同文本去重。以 providerCallId 配对工具事件；终态不被迟到进度覆盖。结果文本去重依赖消息 ID 与协议角色，不使用全文相同判断，避免丢掉合法重复内容。

状态与成功判定

CREATED → STARTING → RUNNING ↔ WAITING_FOR_USER → SUCCEEDED / FAILED / TIMED_OUT / CANCELLED / INTERRUPTED；停止请求进入 CANCELLING。状态由 reducer 处理，不在 Composable 内凭字符串决定。

Agent 成功需要实际版本对应的完成事件、正常退出和无未决致命错误；退出码 0 但缺少协议结束事件显示“结果未确认”。Shell 使用进程退出码，不要求 Agent 结束事件。stderr 作为诊断通道，不能一概视作任务失败；工具非零退出要记录失败，但与整轮最终状态区分。未知事件保留，协议解析失败不可被当作普通成功回复。

存储与性能

引入 Room 保存会话索引、轮次及事件投影，事务写入最终回复与终态。重要生命周期事件立即落盘；文本增量可 50–100ms 合并刷新 UI，最终 flush 后才结束。采用带背压的单写入队列，不让数据库或界面卡顿导致丢终态事件。

长输出以分块文件存于 app 私有目录，数据库保存索引；UI 首屏仅加载最近轮次，历史按需分页，LazyColumn 使用稳定 key。建议首版每 run 输出预算 10 MiB，达到预算显示“日志已截断”并保存状态事件、失败摘要及结尾窗口；阈值须设备测试再定，不能默默删旧输出。

网关密钥和真实配置继续只进现有加密存储。CLI 输出在持久化、显示和导出前经过脱敏；不保存包含凭证的启动命令、环境变量或完整请求头。运行参数记录只含配置引用；未知协议事件也必须脱敏。会话数据库退出系统自动备份；对话内容本身仍可能敏感，后续若加导出必须让用户选择范围。

9. 分阶段实施与验收门槛

阶段实施内容完成证据
A：结构基础用结构化事件替换文本压平；分离诊断日志；不改变网关主路径固定 CLI 版本的脱敏真实事件夹具覆盖工具、失败、完成、未知事件
B：可继续的历史Room、CLI session 绑定、草稿、单运行实例路由切换/旋转/重建后不串会话；两种 CLI 实测恢复上下文；异常如实呈现
C：对话界面对话主屏、抽屉、Navigation Compose、时间线、折叠、全屏详情、IME 与停止Compose 交互测试 + 320/360/412dp、横屏、IME、200% 字号验收
D：强化交互真实审批回传、语音/上下文能力、文件差异真 CLI + 模拟网关，再以手机真实网关验收

阶段 C 可先用明确标注的演示事件验证交互；产品入口不能在 B 未完成时声称支持连续对话。阶段 D 的审批未验证前不开放对应按钮。只在实际获取到文件改动信息时显示“查看改动”，不从回复文字推断。

关键验收用例：

  1. 新运行默认展开；正常结束时最终答复可见、过程变摘要；点摘要恢复步骤。
  2. 用户手动打开详情，完成事件不能关闭它；用户手动收起后新 token 不能再打开。
  3. 上滑查看历史时新输出不抢滚动，完成折叠不造成视口跳跃。
  4. 失败、超时、取消、权限请求不被父组折叠遮住；重试保留旧轮次。
  5. 切换到 B 后，A 的日志仍写 A；B 的草稿保持；全局执行锁不失效。
  6. 旋转与进程重建后历史、手动折叠、草稿恢复；无运行证据时不显示完成或自动重发。
  7. 未知事件、重复快照、迟到输出、缺少结束事件均不造成重复回复或假成功。
  8. 10,000 个输出事件下可滚动、停止可响应、内存有界；截断显式可见。
  9. TalkBack 可读出状态和展开语义；目标触区 ≥48dp；200% 大字体与键盘不遮住发送/停止；深浅色可读。
  10. 系统返回先收 IME，详情返回恢复位置；预测返回取消不改变导航；归档撤销有效；通知冷启动直达运行对话；根页返回交给系统。
  11. 覆盖升级保留 applicationId、Keystore 别名、SharedPreferences、HOME、工作区；既有日志无法可靠迁移为对话时不伪造历史。
  12. 侧栏搜索/切换/新建项目后草稿与附件不串；关闭抽屉恢复阅读。
  13. 语音取消不发消息；录音中后台切换、拒绝权限、转写失败均可恢复到文字输入。
  14. 代码复制的是原始代码，切换换行不改内容；全屏返回恢复焦点与位置；引用解析失败不露内部标记。

实施时对可复现问题先补失败回归测试，再改代码。执行项目约定的 Node/Python 测试和 JDK 17 下的 assembleDebug、单元测试、lint；变更涉及网关或 CLI 时跑对应 cli-smoke。模拟成功不等于手机或真实网关通过。本次仅设计文档，不执行完整 Android 构建。

10. 交付范围与 Review 决策

  • 主交互采用对话主屏、模态会话侧栏、胶囊工具栏、底部输入、步骤卡与全屏代码。
  • 首版必须打通文本对话、CLI 会话恢复、单执行锁、历史、草稿、折叠、停止、网关配置与真实异常。
  • 项目分组只组织可用工作区；语音、文件/图片、审批回传按能力分阶段开放。HTML 原型中的这些流程均明确为示例。
  • 参考图的“快速/进阶”改为实际 Agent 和模型信息；隐藏推理、乱码引用、账号/扫码、定时任务与生成 PPT 不照搬。
  • HTML 可体验侧栏搜索、新建项目/对话、重命名、置顶/归档/恢复、状态折叠、详情、代码、语音校对、附件移除与主题；设置为只读布局预览，不保存真实配置。

评审重点：侧栏分组与入口是否顺手；执行卡的信息密度是否合适；语音先校对再入草稿是否符合预期；首版与后续能力边界是否清晰。HTML 不替代 Android 手势、真实键盘、TalkBack、真实语音和模型调用验收。
